::: {.lead}
라면 봉지 뒷면에는 끓이는 법이 적혀 있습니다. 물을 끓이고, 면과 스프를 넣고, 4분 더 끓입니다. 위에서부터 한 줄씩 따라 하면 라면이 됩니다. 코드도 컴퓨터가 위에서부터 한 줄씩 따라 하는 지시문입니다. 여기서는 분식 가게의 주문을 계산하는 작은 프로그램을 조금씩 키워 가며, AI가 써 준 코드를 읽는 법을 익힙니다.
:::

::: {.goals}
- AI가 준 코드를 위에서부터 읽고 무슨 일을 하는지 말할 수 있습니다.
- 변수, 갈림길, 되풀이, 함수를 코드에서 알아볼 수 있습니다.
- 오류 글에서 오류의 이름, 파일 이름, 줄 번호를 찾을 수 있습니다.
- 프로젝트 폴더에서 먼저 열 파일과 건드리지 않을 폴더를 가려낼 수 있습니다.
:::

## 코드는 위에서 아래로 읽는 지시문입니다 {#recipe}

민아네 반은 학교 축제에서 분식 가게를 엽니다. 김밥은 3,000원, 라면은 4,000원, 떡볶이는 3,500원입니다. 민아는 AI에게 주문 합계를 계산하는 프로그램을 부탁했습니다. 돌아온 것은 영어와 기호가 섞인 글 몇 줄이었습니다.

컴퓨터에게 시킬 일을 적은 이런 글이 **코드**(code)입니다. 코드를 적을 때 쓰는 말은 프로그래밍 언어라고 합니다. 아래는 **파이썬**(Python)이라는 프로그래밍 언어로 쓴 코드입니다. 뒤에 나오는 코드도 따로 말하지 않으면 파이썬입니다.

```python
# 분식집 주문 합계
print("주문을 계산합니다")
print(3000 + 4000)
print("끝")
```

코드의 줄은 맨 위부터 1번, 2번 하고 번호로 부릅니다. 빈 줄도 한 줄로 셉니다.

- **1번 줄**은 `#`으로 시작합니다. `#` 뒤의 글은 사람이 읽으라고 적어 둔 메모입니다. 이런 메모를 **주석**(comment)이라고 합니다. 컴퓨터는 주석을 건너뜁니다.
- **2번 줄**의 `print`는 괄호 안의 것을 화면에 찍으라는 지시입니다. 따옴표 안의 글자가 그대로 찍힙니다.
- **3번 줄**은 3000 + 4000을 먼저 계산하고 답을 찍습니다.
- **4번 줄**은 "끝"이라고 찍습니다.

컴퓨터가 코드에 적힌 대로 일하는 것을 **실행**이라고 합니다. 이 코드를 실행하면 화면에 세 줄이 찍힙니다.

::: {.fig src="top-down.svg"}
코드가 한 줄씩 실행될 때마다 화면에 한 줄씩 찍힙니다. 주석인 1번 줄은 건너뜁니다.
:::

컴퓨터는 코드를 **위에서 아래로, 한 줄씩 차례로** 실행합니다. 앞줄이 끝나야 다음 줄로 갑니다. 그래서 읽는 사람도 위에서부터 읽습니다. 줄마다 "이 줄이 끝나면 무엇이 달라지나"를 묻습니다.

::: {.note title="주석은 설명일 뿐입니다"}
AI가 준 코드에는 주석이 많아서 훑어보기 좋습니다. 하지만 주석은 실행되지 않습니다. 주석에 "합계를 계산"이라고 적혀 있어도, 정말 그 일을 하는지는 아래 코드를 보고 확인합니다.
:::

## 값과 변수: 이름표 붙인 통 {#value}

분식집 주방에는 반찬통이 여럿 있습니다. 통마다 '단무지', '어묵' 하고 이름표를 붙여 둡니다. 이름표를 보고 통을 찾고, 안에 든 것은 언제든 바꿔 담습니다.

코드에도 이런 통이 있습니다. 숫자나 글자 같은 값을 담아 두고 이름을 붙인 칸입니다. 이 칸을 **변수**(variable)라고 합니다. 파이썬 코드로 적으면 이렇습니다.

```python
menu = "김밥"
price = 3000
count = 2
is_takeout = True
coupon = None
print(menu, price * count)
```

- **1~5번 줄**은 변수 다섯 개를 만듭니다. `=`의 왼쪽이 이름이고 오른쪽이 담을 값입니다. 이름은 코드를 쓴 쪽이 알아보기 좋게 지은 것입니다. 이름에는 빈칸을 쓸 수 없어서 `is_takeout`처럼 낱말을 밑줄 `_`로 잇습니다.
- `menu`에는 글자 "김밥"을 담았습니다. 따옴표로 감싼 글자를 **문자열**(string)이라고 합니다.
- `price`(가격)와 `count`(개수)에는 따옴표 없이 숫자를 담았습니다.
- `is_takeout`은 "포장인가?"에 답하는 변수입니다. `True`는 참, `False`는 거짓입니다. 참과 거짓 둘뿐인 이 값을 불리언(boolean)이라고 합니다.
- `coupon`에 담은 `None`은 "아직 없음"이라는 표시입니다. 숫자 0과도, 빈 글자와도 다릅니다.
- **6번 줄**은 쉼표로 나눠 적은 둘을 한 줄에 나란히 찍습니다. `*`는 곱하기입니다. 3000 × 2 = 6000이니 `김밥 6000`이 찍힙니다.

::: {.fig src="value-boxes.svg"}
변수는 이름표 붙인 통입니다. 자주 담는 값 네 가지를 그렸습니다. 따옴표가 있으면 글자입니다.
:::

**`=`는 "같다"가 아니라 "넣는다"입니다.** `count = count + 1`이라는 줄을 봅시다. 수학에서는 말이 안 되는 식입니다. 코드에서는 "오른쪽을 먼저 계산해서 왼쪽 통에 넣어라"로 읽습니다. `count`가 2였다면 2 + 1 = 3이 새로 담깁니다. 전에 있던 2는 사라집니다.

**따옴표는 "이것은 글자"라는 표시입니다.** 큰따옴표 `"김밥"`과 작은따옴표 `'김밥'`은 같은 뜻입니다. `3000 + 4000`은 7000입니다. `"3000" + "4000"`은 `30004000`입니다. 따옴표 안의 3000은 숫자처럼 보여도 글자이고, 글자끼리 `+`를 하면 이어 붙기 때문입니다.

::: {.tip title="합계가 이상하게 길면"}
화면의 입력 칸에 사람이 친 값은 대개 문자열로 들어옵니다. 합계가 30004000처럼 나오면 이것부터 살핍니다. 문자열을 숫자로 바꾸는 `int(…)`가 빠졌는지 봅니다.
:::

## 여러 개 담기: 리스트와 딕셔너리 {#collection}

손님 한 명이 여러 개를 시키면 주문서에 메뉴가 줄줄이 적힙니다. 벽의 메뉴판에는 메뉴 이름 옆에 가격이 적혀 있습니다. 코드에도 주문서와 메뉴판이 있습니다.

```python
orders = ["김밥", "라면", "김밥"]
prices = {"김밥": 3000, "라면": 4000, "떡볶이": 3500}
print(orders[0])
print(len(orders))
print(prices["라면"])
```

- **1번 줄**은 주문서입니다. 대괄호 `[ ]` 안에 값을 쉼표로 나눠 차례로 적었습니다. 이렇게 차례로 담은 것을 **리스트**(list)라고 합니다.
- **2번 줄**은 메뉴판입니다. 중괄호 `{ }` 안에 `이름: 값` 짝을 적었습니다. 이렇게 짝지어 담은 것을 **딕셔너리**(dictionary)라고 합니다. 이름 쪽을 키(key)라고 부릅니다.
- **3번 줄**의 `orders[0]`은 "0번 칸을 꺼내라"입니다. 칸 번호는 0부터 셉니다. 첫 칸인 "김밥"이 찍힙니다.
- **4번 줄**의 `len`은 몇 개가 들었는지 셉니다. 괄호가 겹치면 안쪽부터 합니다. `len(orders)`가 먼저 3이 되고, 그 3을 `print`가 찍습니다.
- **5번 줄**의 `prices["라면"]`은 "라면이라는 키의 값을 꺼내라"입니다. 4000이 찍힙니다.

::: {.fig src="list-dict.svg"}
리스트는 번호로, 딕셔너리는 이름으로 꺼냅니다. 번호는 0부터 시작합니다.
:::

::: {.note}
세 개가 든 리스트의 마지막 칸은 2번입니다. 없는 칸 `orders[3]`을 꺼내려 하면 오류가 나고 멈춥니다.
:::

리스트 안에 딕셔너리를 담을 수도 있습니다. 메뉴마다 몇 개인지까지 적은 주문서입니다.

```python
orders = [
    {"menu": "김밥", "count": 2},
    {"menu": "라면", "count": 1},
]
print(orders[1]["menu"])
```

- **1~4번 줄**은 리스트 하나를 여러 줄에 나눠 적은 것입니다. 안에 딕셔너리가 두 개 들어 있습니다.
- **5번 줄**은 왼쪽부터 읽습니다. `orders`의 1번 칸인 둘째 딕셔너리에서 `"menu"`의 값을 꺼냅니다. "라면"이 찍힙니다.

앱이 주고받는 데이터는 대개 이렇게 겹친 모양입니다. 대괄호를 보면 "여러 개가 차례로", 중괄호를 보면 "이름과 값의 짝"이라고 읽습니다.

리스트는 배열, 딕셔너리는 해시 맵이나 객체라고도 부릅니다. 이름이 달라도 읽는 법은 같습니다([8장](ch08.html#array)).

## 갈림길: if와 else {#branch}

배달 앱에는 "12,000원 이상 주문하면 배달비 무료" 같은 글이 붙어 있습니다. 합계에 따라 길이 둘로 갈립니다. 민아의 가게도 교실까지 배달을 합니다. 배달비는 2,000원입니다.

```python
total = 10000
if total >= 12000:
    delivery = 0
    print("배달비 무료")
else:
    delivery = 2000
print(total + delivery)
```

- **1번 줄**은 합계 `total`에 10000을 넣습니다.
- **2번 줄**의 `if`는 "만약 ~이면"입니다. `>=`는 "크거나 같다"입니다. 줄 끝의 `:`은 "여기부터 묶음"이라는 표시입니다.
- **3~4번 줄**은 안쪽으로 들여 쓴 묶음입니다. 조건이 참일 때만 실행됩니다. 배달비 `delivery`에 0을 넣고 글을 찍습니다.
- **5~6번 줄**의 `else`는 "그렇지 않으면"입니다. 6번 줄은 조건이 거짓일 때만 실행됩니다.
- **7번 줄**은 들여쓰기가 끝난 줄입니다. 어느 길로 왔든 실행됩니다.

10000은 12000보다 작으니 조건은 거짓입니다. `delivery`에 2000이 담기고, 10000 + 2000 = 12000이 찍힙니다. 조건에 따라 갈라지는 이런 코드를 **조건문**이라고 합니다.

::: {.fig src="branch-indent.svg"}
들여 쓴 줄은 바로 위의 `if`나 `else`에 딸린 묶음입니다. 합계가 10000이면 주황색 길로 갑니다.
:::

**파이썬에서는 줄 앞의 빈칸이 뜻을 정합니다.** 이 빈칸을 **들여쓰기**라고 합니다. 한 단은 보통 빈칸 네 개입니다. 7번 줄을 안쪽으로 들여 쓰면 `else`에 딸린 줄이 됩니다. 그러면 배달비가 무료인 손님에게는 합계가 찍히지 않습니다.

조건에는 아래 기호를 씁니다.

| 기호 | 뜻 | `total`이 10000일 때 |
|---|---|---|
| `==` | 같다 | `total == 10000`은 참 |
| `!=` | 다르다 | `total != 10000`은 거짓 |
| `>` | 크다 | `total > 10000`은 거짓 |
| `>=` | 크거나 같다 | `total >= 10000`은 참 |

`<`는 "작다", `<=`는 "작거나 같다"입니다. `=` 하나는 넣는다는 뜻이고, `==` 둘은 같은지 묻는다는 뜻입니다.

길이 셋 이상으로 갈리면 `if`와 `else` 사이에 `elif`가 낍니다. "그렇지 않고 만약 ~이면"입니다.

조건을 잇는 낱말도 있습니다. `and`는 "둘 다 참일 때만", `or`는 "하나라도 참이면", `not`은 "반대로"입니다. `if total >= 12000 or is_member:`는 "12,000원 이상이거나 단골이면"으로 읽습니다. 참과 거짓을 조합하는 표는 [초수학 기초](math.html#cheatsheet)에 있습니다.

::: {.tip title="딱 그 값일 때를 넣어 봅니다"}
"12,000원 이상"을 부탁했는데 AI가 `>`로 쓰는 일이 있습니다. 그러면 딱 12,000원인 주문에 배달비가 붙습니다. 조건문을 보면 **경계에 선 값**이 어느 길로 가는지 따져 봅니다.
:::

## 되풀이: for와 while {#loop}

계산대에서는 주문서를 위에서부터 한 줄씩 짚어 가며 계산기에 더합니다. 줄이 셋이면 같은 일을 세 번 합니다. 코드로는 이렇게 적습니다.

```python
orders = ["김밥", "라면", "김밥"]
prices = {"김밥": 3000, "라면": 4000, "떡볶이": 3500}
total = 0
for menu in orders:
    total = total + prices[menu]
print(total)
```

- **1~2번 줄**은 앞에서 본 주문서와 메뉴판입니다.
- **3번 줄**은 `total`을 0으로 둡니다. 계산기를 0으로 맞추는 일입니다.
- **4번 줄**은 "`orders`에서 하나씩 꺼내 `menu`에 넣고, 그때마다 아래 묶음을 실행하라"입니다. `menu`는 이 줄에서 새로 만든 변수입니다.
- **5번 줄**이 되풀이되는 묶음입니다. 메뉴판 `prices`에서 `menu`의 가격을 찾아 `total`에 더합니다.
- **6번 줄**은 들여쓰기가 끝난 줄입니다. 되풀이가 다 끝난 뒤에 한 번 실행됩니다.

::: {.fig src="loop-rounds.svg"}
주문서의 세 칸을 차례로 돌면서 `total`이 0에서 10000까지 자랍니다.
:::

같은 묶음을 되풀이하는 이런 코드를 **반복문**(loop)이라고 합니다. `for i in range(3):`처럼 생긴 줄도 자주 나옵니다. `i`에 0, 1, 2를 차례로 넣으며 세 번 되풀이하라는 뜻입니다.

몇 번 돌지 미리 모를 때는 `while`을 씁니다. 10,000원으로 3,000원짜리 김밥을 몇 줄 살 수 있는지 세어 봅니다.

```python
money = 10000
count = 0
while money >= 3000:
    money = money - 3000
    count = count + 1
print(count, money)
```

- **1~2번 줄**은 가진 돈 `money`와 산 줄 수 `count`입니다.
- **3번 줄**의 `while`은 "~인 동안"입니다. 조건이 참인 동안 아래 묶음을 되풀이합니다.
- **4~5번 줄**은 돈에서 3000을 빼고 줄 수를 1 늘립니다.

돈은 10000, 7000, 4000, 1000으로 줄어듭니다. 1000은 3000보다 작으니 멈추고 `3 1000`이 찍힙니다. 세 줄을 사고 1,000원이 남았습니다.

::: {.warn title="끝나지 않는 되풀이"}
4번 줄이 빠지면 `money`는 계속 10000입니다. 조건이 늘 참이라 멈추지 않고 돕니다. 이것을 **무한 루프**(infinite loop)라고 합니다. 프로그램이 반응이 없고 컴퓨터 팬 소리가 커지면 의심합니다. 명령을 글로 쳐 넣는 창인 터미널([5장](ch05.html#terminal))에서는 `Ctrl+C`를 눌러 세웁니다.
:::

`while`을 보면 "조건이 언제 거짓이 되나"를 찾습니다. 묶음 안에 조건을 바꾸는 줄이 있어야 합니다.

`while True:`로 시작하는 되풀이도 흔합니다. 조건이 늘 참이라 스스로는 멈추지 않습니다. 이때는 묶음 안에서 "되풀이에서 빠져나가라"는 뜻의 `break`를 찾습니다.

## 함수: 묶어서 이름 붙이기 {#function}

가게에서는 손님이 올 때마다 계산하는 법을 새로 설명하지 않습니다. 계산 담당에게 주문서를 건네면 합계를 말해 줍니다. 코드에서도 자주 하는 일은 묶어서 이름을 붙여 둡니다. 이 묶음이 **함수**(function)입니다.

```python
prices = {"김밥": 3000, "라면": 4000, "떡볶이": 3500}

def get_total(orders):
    total = 0
    for menu in orders:
        total = total + prices[menu]
    return total

print(get_total(["김밥", "라면"]))
print(get_total(["떡볶이"]))
```

- **3번 줄**의 `def`는 "함수를 만든다"입니다. 이름은 `get_total`(합계 구하기)입니다. 괄호 안의 `orders`는 건네받을 주문서에 붙일 이름입니다.
- **4~6번 줄**은 앞 절에서 본 계산입니다.
- **7번 줄**의 `return`은 결과를 부른 곳으로 돌려주고 함수를 끝냅니다.
- **9번 줄**은 함수를 부릅니다. 이름 뒤에 괄호를 붙이고 주문서를 넣었습니다. 7000이 돌아와 화면에 찍힙니다.
- **10번 줄**은 다른 주문서로 또 부릅니다. 3500이 찍힙니다.

함수에 넣는 것을 **인자**(argument), 돌려받는 것을 **반환값**(return value)이라고 합니다. 인자는 인수라고도 부릅니다.

앞에서 쓴 `print`와 `len`도 함수입니다. 파이썬에 처음부터 들어 있어서 `def` 없이 부르기만 했습니다.

::: {.fig src="function-call.svg"}
함수는 한 번 만들고 여러 번 부릅니다. 부를 때마다 인자가 들어가고 반환값이 돌아옵니다.
:::

**만드는 것과 부르는 것은 다릅니다.** 함수를 만드는 일을 정의, 부르는 일을 **호출**(call)이라고 합니다. 3~7번 줄은 방법을 적어 둔 것입니다. 컴퓨터는 그 줄을 지나며 "이런 함수가 있다"고 기억만 해 둡니다. 9번 줄에서 부를 때에야 3번 줄로 올라가 묶음을 실행합니다. 그래서 `def` 묶음은 "이런 함수가 있구나" 하고 넘어갔다가, 부르는 줄을 만나면 돌아와 읽습니다.

함수를 읽을 때는 이름, 넣는 것, 돌려주는 것부터 찾습니다. 이름과 실제로 하는 일이 다르면 AI에게 묻습니다. 4번 줄의 `total`처럼 함수 안에서 만든 변수는 함수 밖에서 쓸 수 없습니다([10장](ch10.html#function)).

::: {.myth title="print로 찍었으니 결과를 돌려준 것이다"}
`print`는 화면에 찍기만 합니다. `return`이 있어야 부른 곳이 값을 받습니다. `return`이 없는 함수는 `None`을 돌려줍니다. 합계 자리에 `None`이 보이면 `return`이 빠졌는지 살핍니다.
:::

## 남의 코드 가져다 쓰기: import {#import}

분식집은 단무지를 직접 담그지 않고 사다 씁니다. 코드도 그렇습니다. 남이 잘 만들어 둔 함수 묶음을 가져다 씁니다. 이런 묶음을 **라이브러리**(library)라고 합니다.

```python
import math

print(math.ceil(10000 / 3))
```

- **1번 줄**의 `import`는 "가져오다"입니다. `math`는 수학 라이브러리입니다.
- **3번 줄**은 10,000원을 세 명이 나눠 낼 때 한 사람 몫을 구합니다. `/`는 나누기이고 답은 3333.33…입니다. `math.ceil`은 올림이라서 3334가 찍힙니다.

**점(`.`)은 "~안의"로 읽습니다.** `math.ceil`은 "`math` 안의 `ceil`"입니다. 값에도 점을 붙입니다. `orders.append("라면")`은 "`orders` 리스트에 딸린 `append`를 불러 라면을 끝에 덧붙여라"입니다.

가져오는 줄의 모양은 세 가지입니다.

| 코드 | 읽는 법 |
|---|---|
| `import math` | `math`를 통째로 가져옵니다. 쓸 때는 `math.ceil(…)` |
| `from math import ceil` | `math`에서 `ceil`만 꺼내 옵니다. 쓸 때는 `ceil(…)` |
| `import numpy as np` | `numpy`를 가져와 `np`라는 짧은 별명으로 부릅니다 |

가져올 코드가 있는 곳은 세 군데입니다.

- **언어에 처음부터 들어 있는 것.** `math`가 그렇습니다. 따로 설치하지 않습니다.
- **따로 설치하는 것.** 표의 `numpy`는 숫자 계산 라이브러리입니다. 설치하기 좋게 포장한 라이브러리를 **패키지**(package)라고 합니다([6장](ch06.html#package)). 설치하지 않고 실행하면 `ModuleNotFoundError: No module named 'numpy'`라는 오류가 납니다. "numpy라는 모듈이 없다"는 뜻입니다. 모듈은 가져올 수 있는 코드 파일입니다.
- **같은 프로젝트의 다른 파일.** `from menu import prices`는 같은 폴더의 `menu.py`에서 `prices`를 가져옵니다.

파일 맨 위에 모인 `import` 줄은 재료 목록입니다. 이 파일이 바깥의 무엇에 기대는지 보입니다.

::: {.warn title="AI는 없는 것을 지어내기도 합니다"}
AI는 있지도 않은 패키지나 함수 이름을 그럴듯하게 적을 때가 있습니다([27장](ch27.html#hallucination)). 처음 보는 패키지는 설치하기 전에 "이 패키지는 무슨 일을 하고 왜 필요해?"라고 묻습니다. 패키지를 모아 둔 공식 사이트에서 그 이름을 찾아 철자까지 맞춰 봅니다([19장](ch19.html#outside)).
:::

## 오류 글 읽기와 오류에 대비하기 {#error}

손님이 메뉴판에 없는 돈가스를 주문했습니다. 계산 담당은 값을 찾지 못해 멈춰 섭니다. 코드도 똑같이 멈춥니다.

앞 절에서 함수를 만든 코드를 `order.py`라는 파일에 담고 끝의 두 줄을 바꿉니다. 9번 줄에서 주문서 `["김밥", "돈가스"]`를 `order`에 담고, 10번 줄에서 `print(get_total(order))`로 함수를 부릅니다.

터미널에 `python3 order.py`라고 쳐서 실행하면 합계 대신 그림 같은 글이 쏟아집니다. 파일은 민아 컴퓨터의 `bunsik` 폴더에 있습니다.

::: {.fig src="error-read.svg"}
오류 글은 맨 아랫줄부터, 그림의 번호 순서로 읽습니다.
:::

1. **맨 아랫줄부터 읽습니다.** `KeyError: '돈가스'`입니다. 앞은 오류의 이름이고 뒤는 내용입니다. `KeyError`는 "딕셔너리에 그런 키가 없다"입니다.
2. **바로 위 묶음이 멈춘 곳입니다.** `File` 뒤는 파일의 자리와 이름입니다. `line 6, in get_total`은 "`get_total` 함수 안의 6번 줄"입니다. 그 아래가 6번 줄의 코드입니다. `~`와 `^`는 문제가 된 부분에 그은 밑줄입니다. 파이썬 버전에 따라 밑줄의 모양이 다르거나 없기도 합니다.
3. **그 위 묶음은 지나온 길입니다.** 10번 줄에서 함수를 불렀습니다. `<module>`은 함수 밖, 곧 파일의 맨 바깥입니다.

첫 줄의 영어는 "가장 나중에 부른 것이 맨 아래"라는 안내입니다. 지나온 길을 적은 이 글을 **스택 트레이스**(stack trace)라고 합니다. 더 깊이 읽는 법은 [12장](ch12.html#trace)에 있습니다. 자주 보는 오류 이름은 이렇습니다.

| 오류 이름 | 뜻 | 먼저 볼 것 |
|---|---|---|
| `SyntaxError`, `IndentationError` | 문법이나 들여쓰기가 틀렸다 | 괄호와 따옴표의 짝, 줄 앞의 빈칸 |
| `NameError` | 그런 이름이 없다 | 이름의 오타 |
| `TypeError` | 값의 종류가 맞지 않는다 | 숫자 자리에 문자열이나 `None`이 왔는지 |
| `KeyError`, `IndexError` | 그런 키, 그런 번호가 없다 | 딕셔너리의 키, 리스트의 길이 |
| `AttributeError` | 점 뒤의 이름이 그 안에 없다 | AI가 지어낸 이름인지, 점 앞의 값이 `None`인지 |
| `FileNotFoundError` | 그런 파일이 없다 | 경로와 서 있는 폴더([5장](ch05.html#path)) |

AI에게 오류를 알릴 때는 맨 아랫줄만 잘라 주지 않습니다. **처음부터 끝까지 통째로** 붙여 넣고, 무엇을 하다가 났는지 한 줄을 덧붙입니다.

### 미리 대비하기: try와 except

메뉴판에 없는 주문이 와도 가게 문을 닫을 일은 아닙니다. "그 메뉴는 없습니다" 하고 다음으로 넘어가면 됩니다. 함수를 이렇게 고칩니다.

```python
def get_total(orders):
    total = 0
    for menu in orders:
        try:
            total = total + prices[menu]
        except KeyError:
            print("메뉴판에 없습니다:", menu)
    return total
```

- **4~5번 줄**의 `try`는 "아래 묶음을 일단 해 봐라"입니다.
- **6~7번 줄**의 `except KeyError`는 "하다가 `KeyError`가 나면 멈추지 말고 이 묶음을 실행하라"입니다.

다시 실행하면 멈추지 않습니다. `메뉴판에 없습니다: 돈가스`가 찍히고, 이어서 김밥만 더한 3000이 찍힙니다.

::: {.warn title="오류를 삼키는 코드"}
`except` 아래에 `pass` 한 줄만 있는 코드가 있습니다. `pass`는 "아무것도 하지 않는다"입니다. 오류가 나도 조용히 넘어가니 고장 난 줄도 모릅니다. AI는 오류 글을 없애려고 이런 코드를 쓰곤 합니다. `except Exception:`은 오류의 이름을 가리지 않고 다 받겠다는 줄이라 더 조심합니다. `except` 묶음에서는 **오류가 났을 때 무엇을 하기로 했는지** 읽습니다.
:::

## 파이썬과 자바스크립트 나란히 {#two-languages}

'학교'를 영어로는 school이라고 씁니다. 낱말은 달라도 가리키는 것은 같습니다. 프로그래밍 언어도 그렇습니다.

웹 화면을 만들어 달라고 하면 AI는 대개 **자바스크립트**(JavaScript)라는 언어로 씁니다. 같은 합계 계산을 자바스크립트로 적으면 이렇습니다.

```javascript
const prices = { "김밥": 3000, "라면": 4000, "떡볶이": 3500 };

function getTotal(orders) {
  let total = 0;
  for (const menu of orders) {
    total = total + prices[menu];
  }
  return total;
}
console.log(getTotal(["김밥", "라면", "김밥"]));
```

- **1번 줄**의 `const`와 4번 줄의 `let`은 변수를 만드는 낱말입니다. `const`로 만든 변수에는 값을 다시 넣지 못하고, `let`으로 만든 변수에는 다시 넣을 수 있습니다. 옛 코드에는 `var`도 보입니다.
- **3번 줄**의 `function`은 파이썬의 `def`입니다. 함수의 묶음은 `{`에서 9번 줄의 `}`까지입니다.
- **5번 줄**은 파이썬의 `for menu in orders:`와 같습니다.
- **10번 줄**의 `console.log`는 `print`입니다. 10000이 찍힙니다. 줄 끝의 `;`은 한 문장이 끝났다는 표시입니다.

| 하는 일 | 파이썬 | 자바스크립트 |
|---|---|---|
| 묶음 표시 | `:`과 들여쓰기 | 중괄호 `{ }` |
| 변수 만들기 | `total = 0` | `let total = 0;` 또는 `const` |
| 함수 만들기 | `def get_total(orders):` | `function getTotal(orders) { }` |
| 화면에 찍기 | `print(…)` | `console.log(…)` |
| 없음, 참, 거짓 | `None`, `True`, `False` | `null`, `true`, `false` |
| 같은지 묻기 | `==` | `===` |
| 주석 | `#` | `//` |
| 오류 대비 | `try`, `except` | `try`, `catch` |
| 여러 개 담기 | 리스트, 딕셔너리 | 배열, 객체 |

자바스크립트에서는 들여쓰기가 아니라 중괄호가 뜻을 정합니다. 그래서 닫는 `}`가 어느 `{`와 짝인지 봅니다. `and`, `or`, `not`은 `&&`, `||`, `!`로 적습니다. 함수를 `(orders) => { }`처럼 화살표로 짧게 적은 코드도 자주 나옵니다.

::: {.warn}
파이썬은 메뉴판에 없는 `prices["돈가스"]`에서 멈춥니다. 자바스크립트는 멈추지 않고 '정해진 적 없음'을 뜻하는 `undefined`를 내줍니다. 거기에 3000을 더하면 '숫자가 아님'을 뜻하는 `NaN`이 됩니다. 화면에 `undefined`나 `NaN`이 보이면 없는 것을 꺼냈는지 살핍니다([8장](ch08.html#empty)).
:::

오류 글의 순서도 다릅니다. 자바스크립트의 오류 글은 오류의 이름이 위쪽에 있습니다. 그 아래로 흔히 `at`으로 시작하는 줄이 이어집니다. 첫 `at` 줄이 멈춘 곳이고, 아래로 갈수록 먼저 지나온 곳입니다. 줄 끝의 `app.js:12:5`는 "`app.js` 파일의 12번 줄, 5번째 칸"입니다.

파일 이름이 `.py`로 끝나면 파이썬, `.js`면 자바스크립트, `.ts`면 **타입스크립트**(TypeScript)입니다. 타입스크립트는 자바스크립트에 값의 종류를 적어 둔 언어입니다. 값의 종류를 **타입**(type)이라고 합니다.

타입스크립트에서는 함수의 첫 줄이 `function addFee(total: number): number {`처럼 생겼습니다. `total: number`는 "`total`에는 숫자만 온다"입니다. 괄호 뒤의 `: number`는 "돌려주는 것도 숫자"입니다. `addFee("10000")`처럼 문자열을 넣으면 실행하기 전에 잘못을 알려 줍니다([4장](ch04.html#errors)).

## 프로젝트 폴더 읽기 {#project}

처음 간 도서관에서는 안내도부터 봅니다. 어느 층에 무엇이 있는지 알아야 책을 찾습니다.

AI에게 앱을 만들어 달라고 하면 흔히 파일 하나가 아니라 폴더 하나가 통째로 생깁니다. 이 폴더가 프로젝트 폴더입니다([5장](ch05.html#project)). 파일이 수십 개여도 대하는 법은 크게 네 가지입니다.

::: {.fig src="project-tree.svg"}
분식 가게 프로젝트 폴더. 색은 대하는 법, 번호는 여는 순서입니다.
:::

| 파일과 폴더 | 무엇인가 | 대하는 법 |
|---|---|---|
| `README.md` | 설명서 | 가장 먼저 읽습니다 |
| `requirements.txt`, `package.json` | 필요한 패키지 목록 | 쓰는 언어와 패키지를 읽습니다 |
| `main.py`, `index.js`, `src/` | 시작 파일과 사람이 쓴 코드 | 읽고 고칩니다 |
| `.env` | 비밀번호 같은 비밀 값 | 남에게 보여 주지 않습니다 |
| `.gitignore` | 저장 지점을 쌓는 도구 Git에 담지 않을 이름 목록([7장](ch07.html#stage)) | `.env`가 적혀 있는지 봅니다 |
| `package-lock.json` 같은 잠금 파일 | 설치된 패키지의 정확한 버전([6장](ch06.html#package)) | 손으로 고치지 않고, 지우지도 않습니다 |
| `node_modules/`, `.venv/`, `.git/` | 도구가 관리하는 폴더 | 열어서 고치지 않습니다 |

여는 순서는 그림의 번호대로입니다. 설명서, 패키지 목록, 시작 파일을 차례로 엽니다. 시작 파일은 프로그램이 처음 실행하는 파일이고 `main`, `app`, `index` 같은 이름이 많습니다. 어느 파일인지 모르겠으면 설명서에 적힌 켜는 명령을 봅니다. `python3 main.py`라면 `main.py`입니다. 그다음에는 `import` 줄을 따라 다른 파일로 넘어갑니다.

`package.json`은 코드가 아니라 설정을 적은 파일입니다. **JSON**이라는 방식으로 적습니다([8장](ch08.html#exchange)). 분식 가게의 웹 화면을 자바스크립트로 만들었다면 이렇게 생겼습니다.

```json
{
  "scripts": {
    "dev": "node server.js"
  },
  "dependencies": {
    "express": "^4.19.2"
  }
}
```

- 딕셔너리처럼 중괄호 안에 `이름: 값` 짝이 겹쳐 있습니다.
- **`scripts`**는 자주 쓰는 명령에 붙인 별명입니다. 터미널에 `npm run dev`라고 치면 `node server.js`가 실행됩니다. `npm`은 자바스크립트의 패키지 도구이고, `node`는 자바스크립트를 실행하는 프로그램입니다. 프로그램을 켜는 법이 여기 있습니다.
- **`dependencies`**는 필요한 패키지와 버전입니다. `express`는 패키지 이름입니다. `^`의 뜻은 [20장](ch20.html#semver)에 있습니다.

설정 파일은 **YAML**이라는 방식으로도 적습니다. 파일 이름이 `.yaml`이나 `.yml`로 끝납니다. 중괄호 대신 들여쓰기로 안과 밖을 나타냅니다. `delivery:` 줄 아래에 `fee: 2000`을 들여 쓰면 "`delivery` 안의 `fee`는 2000"이라는 뜻입니다.

::: {.warn title="건드리지 않는 것 셋"}
`.env`의 비밀 값은 AI 대화창에도 붙여 넣지 않습니다([6장](ch06.html#env)). `node_modules/`와 `.venv/`에는 설치한 패키지가 들어 있습니다. 꼬이면 지우고 다시 설치합니다. `.git/`에는 Git의 저장 지점이 쌓여 있어서, 지우면 지난 기록이 사라집니다([7장](ch07.html)).
:::

AI가 만든 폴더를 받으면 세 가지를 확인합니다.

- **설명서에 켜는 명령이 적혀 있는가.** 없으면 적어 달라고 합니다.
- **`.gitignore`에 `.env`가 적혀 있는가.** AI가 `.env`를 만들고도 이 목록에 넣지 않을 때가 있습니다.
- **코드가 `import`하는 패키지가 패키지 목록에도 있는가.** 빠져 있으면 다른 컴퓨터에서 `ModuleNotFoundError`가 납니다.

AI는 있던 파일을 고치는 대신 `main_new.py` 같은 새 파일을 만들기도 합니다. 비슷한 이름의 파일이 둘이면 어느 쪽이 실제로 실행되는지 묻습니다.

::: {.try}
AI가 만들어 준 프로젝트 폴더가 있으면 AI에게 물어보세요. "이 폴더의 파일이 저마다 무슨 일을 하는지 한 줄씩 알려 줘. 어느 파일부터 실행되는지, 켜는 명령이 무엇인지도 알려 줘. 내가 고쳐도 되는 것과 건드리면 안 되는 것을 나눠 줘."
:::

## AI가 준 코드를 읽는 순서 {#reading}

가정통신문을 받으면 첫 글자부터 차례로 읽지 않습니다. 무슨 일인지, 무엇을 언제까지 내야 하는지부터 찾습니다. 긴 코드도 그렇게 읽습니다.

민아가 "주문 내역을 파일로 저장해 줘"라고 하자 AI가 이런 파이썬 코드를 줬습니다.

```python
import json
import os

def save_orders(orders, path):
    if os.path.exists(path):
        os.remove(path)
    try:
        with open(path, "w", encoding="utf-8") as f:
            json.dump(orders, f, ensure_ascii=False)
    except OSError:
        pass
```

모르는 낱말이 많아도 네 가지만 차례로 찾습니다.

::: {.fig src="read-order.svg"}
같은 코드에 읽는 순서를 표시했습니다. 번호대로 찾으면 위험한 곳이 보입니다.
:::

1. **무엇이 들어가고 무엇이 나오나.** 4번 줄을 봅니다. 함수 이름은 `save_orders`(주문 저장)입니다. 넣는 것은 주문서 `orders`와 파일의 자리 `path`입니다. `return`이 없으니 돌려주는 것은 없습니다.
2. **바깥과 닿는 곳은 어디인가.** 계산만 하는 줄은 틀려도 다시 하면 됩니다. 파일, 인터넷, 데이터를 모아 두는 데이터베이스([17장](ch17.html))에 쓰거나 지우거나 보내는 줄은 되돌리기 어렵습니다. 6번 줄의 `os.remove`는 파일을 **지웁니다.** 8번 줄의 `open(path, "w")`는 파일을 쓰려고 엽니다. `"w"`로 열면 그 파일에 있던 내용은 지워지고 새로 적힙니다.
3. **갈림길과 오류 처리는 어떤가.** 5번 줄은 "파일이 이미 있으면"입니다. 10~11번 줄은 저장하다 오류가 나도 조용히 넘어갑니다. 그래서 옛 파일을 지운 뒤 저장에 실패하면 옛것도 새것도 남지 않고, 알려 주지도 않습니다.
4. **모르는 줄은 AI에게 묻는다.** 8~9번 줄을 물으면 이런 답이 옵니다. `with open(…) as f:`는 파일을 열어 `f`라는 이름으로 쓰고, 묶음이 끝나면 알아서 닫습니다. `json.dump`는 주문서를 JSON 글자로 바꿔 파일에 적습니다. `encoding="utf-8"`과 `ensure_ascii=False`처럼 `이름=값`으로 적은 인자는 설정입니다. 둘 다 한글이 깨지지 않고 그대로 적히게 합니다.

2번을 찾을 때는 아래 낱말이 길잡이입니다.

| 닿는 곳 | 코드에 보이는 낱말 | 물어볼 것 |
|---|---|---|
| 파일 | `open`, `write`, `remove`, `rmtree`, `unlink` | 어느 파일을 쓰고 지우나 |
| 인터넷 | `requests`, `fetch`, `http` | 어디로 무엇을 보내나 |
| 데이터베이스 | `execute`, `UPDATE`, `DELETE`, `DROP` | 무엇을 바꾸고 지우나 |
| 터미널 명령 | `subprocess`, `os.system` | 어떤 명령을 실행하나 |
| 비밀 값 | `os.environ`, `process.env`, `API_KEY` | 값이 코드에 그대로 적혀 있지 않나 |

AI에게는 이렇게 부탁합니다.

> 방금 준 코드를 내가 읽을 수 있게 설명해 줘. (1) 무엇을 넣으면 무엇이 나오는지 한 문장으로. (2) 파일, 인터넷, 데이터베이스를 읽거나 쓰거나 지우는 줄을 줄 번호와 함께 모두. (3) 오류가 나면 어떻게 되는지. 조용히 넘어가는 곳은 따로 말해 줘. (4) 그다음 위에서부터 한 줄씩 쉬운 말로 풀어 줘.

**받은 답에서 확인할 것**

- 설명의 줄 번호가 실제 코드와 맞는가.
- 지우는 줄을 빠뜨리지 않았는가. 찾기 기능으로 `remove`와 `delete`를 직접 찾아봅니다.
- 설명과 코드가 다르지 않은가. AI의 설명도 주석처럼 실행되지 않습니다. 둘이 다르면 실제로 일어나는 것은 코드 쪽입니다.

**AI가 준 코드에서 자주 걸리는 곳**

| 코드에 보이는 것 | 뜻 |
|---|---|
| `except` 아래의 `pass` | 오류를 숨깁니다 |
| 계산 없이 `return 7000`처럼 적힌 값, `sample`, `TODO` | 진짜 대신 넣어 둔 가짜 값입니다 |
| `key`, `password`, `token` 옆의 따옴표 속 긴 글자 | 비밀 값이 코드에 적혀 있습니다 |

이런 실수를 막는 말은 [30장](ch30.html#mistakes)에 있습니다. 걸린 곳은 줄 번호를 짚어 고쳐 달라고 합니다.

> 5~6번 줄의 옛 파일 지우기는 빼 줘. 저장에 실패하면 조용히 넘어가지 말고, 무슨 오류인지 화면에 찍어 줘. 다른 줄은 건드리지 마.

::: {.key}
코드를 다 이해하지 못해도 됩니다. **무엇이 들어가고 나오는지, 어디서 바깥을 건드리는지, 오류가 나면 어떻게 되는지**를 말할 수 있으면 감독할 수 있습니다.
:::

::: {.try}
AI에게 "숫자 맞히기 게임을 파이썬으로 20줄 안에서 만들어 줘"라고 해 보세요. 받은 코드를 네 단계로 읽고, 모르는 줄을 셋 골라 물어봅니다. 시키고 확인하는 순서는 [30장](ch30.html)에서 이어집니다.
:::

## 확인 문제 {#quiz}

::: {.q}
아래 코드를 실행하면 화면에 무엇이 찍힐까요?

```python
price = 3000
count = 2
count = count + 1
print(price * count)
```

::: {.a}
9000이 찍힙니다. 3번 줄은 오른쪽 2 + 1을 먼저 계산해 `count`에 3을 넣습니다. 4번 줄은 3000 × 3을 찍습니다.
:::
:::

::: {.q}
김밥과 라면의 가격을 더하려고 했습니다. 무엇이 찍힐까요? 왜 그럴까요?

```python
a = "3000"
b = "4000"
print(a + b)
```

::: {.a}
`30004000`이 찍힙니다. 따옴표로 감쌌으니 둘 다 문자열이고, 문자열끼리 `+`를 하면 이어 붙습니다.
:::
:::

::: {.q}
아래 코드는 무엇을 찍을까요? 마지막 줄을 안쪽으로 한 단 들여 쓰면 어떻게 달라질까요?

```python
orders = ["김밥", "라면", "김밥"]
n = 0
for menu in orders:
    if menu == "김밥":
        n = n + 1
print(n)
```

::: {.a}
김밥이 몇 번 나오는지 세어 2를 찍습니다. 마지막 줄을 한 단 들여 쓰면 `for`에 딸린 줄이 됩니다. 한 바퀴 돌 때마다 찍혀서 1, 1, 2가 차례로 찍힙니다.
:::
:::

::: {.q}
민아는 "12,000원 이상이면 배달비 무료, 아니면 2,000원을 더해 줘"라고 부탁했습니다. AI가 준 코드입니다. 무엇이 찍힐까요? 부탁과 맞나요?

```python
def add_fee(total):
    if total > 12000:
        return total
    return total + 2000

print(add_fee(12000))
print(add_fee(9000))
```

::: {.a}
14000과 11000이 찍힙니다. 딱 12,000원인 주문에 배달비가 붙었으니 부탁과 다릅니다. `>`는 "크다"라서 12000은 들지 않습니다. "이상"은 `>=`로 써야 합니다.
:::
:::

::: {.q}
AI가 "연습용 폴더를 비우는 함수"라며 준 코드입니다. `shutil.rmtree`는 폴더를 속에 든 것까지 통째로 지웁니다. 어디가 위험할까요?

```python
import shutil

def reset(folder):
    try:
        shutil.rmtree(folder)
    except Exception:
        pass
```

::: {.a}
두 곳입니다. 5번 줄은 넘겨받은 폴더를 통째로 지웁니다. "비운다"고 했지만 폴더까지 사라집니다. 휴지통을 거치지 않으니 되살리기 어렵습니다. 어떤 폴더를 넣어 부르는지 꼭 확인합니다. 6~7번 줄은 어떤 오류가 나도 조용히 넘어갑니다. 지우지 못해도 알 수 없습니다.
:::
:::
