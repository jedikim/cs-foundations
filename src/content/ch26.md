::: {.lead}
"AI가 배운다"는 말은 신기하게 들립니다. 하지만 속을 들여다보면 곱하고, 더하고, 틀린 만큼 숫자를 조금 고치는 일을 되풀이할 뿐입니다. 국의 간을 맞추는 것과 같습니다. 한 숟갈 맛보고, 짜면 물을 넣고 싱거우면 소금을 넣습니다. 이 장에서는 그 계산을 작은 숫자 두세 개로 직접 따라가 봅니다.
:::

::: {.goals}
- 사진이나 글이 AI 안에서 숫자 목록이 된다는 것을 설명할 수 있습니다.
- 두 숫자 목록이 얼마나 비슷한지 계산할 수 있습니다.
- AI가 틀린 정도를 숫자로 재고 그만큼 고쳐 가는 과정을 설명할 수 있습니다.
- AI가 문장에서 중요한 낱말에 집중하는 계산을 따라갈 수 있습니다.
- 학습, 추론, 프롬프트에 넣기가 어떻게 다른지 말할 수 있습니다.
:::

## 무엇이든 숫자 목록으로: 벡터와 모양 {#vector}

곱하고 더하려면 먼저 숫자가 있어야 합니다. 컴퓨터는 "얼큰하다"는 말로는 계산하지 못합니다. 그래서 맛부터 숫자로 적습니다.

급식에 나온 김치찌개에 점수를 매겨 봅시다. **짠맛 3, 매운맛 4**입니다. 짧게 (3, 4)라고 적습니다. 이렇게 정해진 순서로 늘어놓은 숫자 목록을 **벡터**(vector)라고 합니다.

순서가 곧 뜻입니다. 첫 칸이 짠맛이라고 약속했으니 (3, 4)와 (4, 3)은 다른 국입니다. 순서를 헷갈려도 컴퓨터는 알려 주지 않습니다. 틀린 답을 조용히 내놓을 뿐입니다.

사진과 글도 이렇게 바꿉니다. 사진은 작은 점마다 빨강, 초록, 파랑의 밝기를 숫자로 적은 것입니다([2장](ch02.html)). 글은 낱말마다 숫자 목록을 붙여서 다룹니다.

맛은 크기를 잴 수 있지만 국의 '종류'는 그렇지 않습니다. 김치찌개 1, 육개장 2, 미역국 3처럼 번호를 붙이면 곤란합니다. 컴퓨터는 미역국을 "김치찌개의 3배"로 계산해 버립니다.

그래서 종류마다 칸을 하나씩 만들고 맞는 칸에만 1을 적습니다. 김치찌개는 (1, 0, 0), 미역국은 (0, 0, 1)입니다. 반 친구 이름이 적힌 표에서 내 칸에만 동그라미를 치는 것과 같습니다. 이렇게 적는 방법을 **원-핫**(one-hot)이라고 합니다.

::: {.fig src="shapes.svg"}
숫자 하나에서 숫자 묶음까지. 아래에 적힌 모양은 방향마다 칸이 몇 개인지 알려 줍니다.
:::

숫자 하나만 있으면 **스칼라**(scalar)라고 합니다. 한 줄로 늘어놓으면 벡터입니다.

벡터를 여러 줄 쌓은 표는 **행렬**(matrix)입니다. 그림에서는 세 국을 쌓았습니다.

표를 여러 장 겹친 묶음은 **텐서**(tensor)입니다. 오늘의 표와 어제의 표를 겹쳤습니다.

그림 아래의 [3, 2] 같은 표시는 **모양**(shape)입니다. 방향마다 칸이 몇 개인지 적은 것입니다. 벡터는 맛이 2가지라서 [2]입니다. 행렬은 국이 3종, 맛이 2가지라서 [3, 2]입니다. 텐서는 여기에 날 2일이 더해져 [2, 3, 2]입니다. 숫자는 모두 2 × 3 × 2 = 12개입니다.

'날', '국', '맛'처럼 칸을 세는 방향을 **축**이라고 합니다. 숫자 하나뿐인 스칼라에는 축이 없습니다. 숫자 묶음을 만나면 **축마다 무엇을 뜻하는지**부터 확인하세요.

::: {.tip}
축의 순서는 도구마다 다릅니다. 색이 있는 사진 한 장을 [높이, 너비, 색 3]으로도, [색 3, 높이, 너비]로도 적습니다. 축을 헷갈린 코드는 오류 없이 틀린 답을 내기도 합니다. AI에게 "숫자 묶음마다 모양과 축의 뜻을 메모로 적어 줘"라고 하세요.
:::

## 두 벡터는 얼마나 닮았나: 내적과 코사인 유사도 {#similarity}

음악 앱은 내가 듣던 노래와 닮은 노래를 골라 줍니다. 컴퓨터는 "닮았다"를 어떻게 숫자로 만들까요?

김치찌개 (3, 4)를 좋아하는 친구에게 닮은 국을 추천해 봅시다. 후보는 육개장 (6, 8)과 미역국 (5, 0)입니다.

먼저 **같은 자리끼리 곱해서 모두 더합니다.** 육개장이라면 짠맛끼리 3 × 6 = 18, 매운맛끼리 4 × 8 = 32, 더해서 50입니다. 이 계산을 **내적**(dot product)이라고 합니다. 미역국은 3 × 5 + 4 × 0 = 15입니다.

값이 클수록 닮았다고 하면 될까요? 김치찌개를 자기 자신과 내적하면 3 × 3 + 4 × 4 = 25입니다. 육개장(50)이 자기 자신(25)보다 더 닮았다는 이상한 말이 됩니다.

(6, 8)은 (3, 4)의 딱 두 배입니다. 맛의 비율은 같고 두 배로 진할 뿐입니다. 내적은 **진하기까지 점수에 넣습니다.**

벡터를 화살표로 그리면 잘 보입니다([23장](ch23.html)). 오른쪽으로 짠맛만큼, 위로 매운맛만큼 갑니다.

::: {.fig src="cosine.svg"}
세 국을 화살표로 그렸습니다. 내적은 화살표가 길면 커집니다. 코사인 유사도는 방향만 봅니다.
:::

화살표의 **방향**은 맛의 비율이고 **길이**는 진하기입니다. 김치찌개와 육개장은 방향이 같습니다. 맵지 않은 미역국은 옆으로 누워서 김치찌개와 53° 벌어졌습니다.

길이를 구하려면 먼저 칸마다 제곱해서 더합니다. 김치찌개는 3 × 3 + 4 × 4 = 25입니다. 제곱해서 25가 되는 수는 5입니다. 이 5가 길이입니다. 같은 방법으로 육개장은 10, 미역국은 5입니다.

이제 **내적을 두 화살표의 길이로 나눕니다.** 진하기가 지워집니다.

- 김치찌개 자신: 25 ÷ (5 × 5) = 1.0
- 육개장: 50 ÷ (5 × 10) = 1.0
- 미역국: 15 ÷ (5 × 5) = 0.6

이 값을 **코사인 유사도**(cosine similarity)라고 합니다. 방향이 같으면 1, 직각이면 0, 정반대면 −1입니다. 추천할 국은 1.0인 육개장입니다.

### 뜻을 담은 벡터, 임베딩

AI는 낱말이나 글의 뜻도 벡터로 바꿔 둡니다. 뜻을 담은 이 벡터를 **임베딩**(embedding)이라고 합니다. 뜻이 비슷한 글은 방향도 비슷합니다. 그래서 겹치는 글자가 없어도 뜻이 가까운 글을 코사인 유사도로 찾아낼 수 있습니다.

임베딩은 이런 곳에 씁니다.

- **뜻으로 찾는 검색.** "얼큰한 국"이라고 쳐도 "매운 찌개"라고 적힌 글이 나옵니다.
- **추천.** 내가 듣던 노래와 방향이 비슷한 노래를 골라 줍니다.
- **자료를 보고 답하는 AI.** 질문과 가까운 글을 먼저 찾아서 AI에게 건넵니다([29장](ch29.html)).

임베딩을 만들어 주는 AI의 설명에는 "1536차원" 같은 말이 적혀 있습니다. **차원**(dimension)은 벡터의 칸 수입니다. 국의 맛 벡터는 2차원이고, 글의 임베딩은 수백에서 수천 차원입니다.

::: {.warn}
견줄 벡터는 모두 **같은 AI**로 만들어야 합니다. 만든 AI가 다르면 칸마다 뜻이 달라서 유사도가 엉터리로 나옵니다.

유사도 1등은 "가장 가까운 후보"일 뿐입니다. 맞는 글이 하나도 없어도 1등은 나옵니다. "유사도가 낮으면 '찾지 못했다'고 답하게 해 줘"라고 시키세요.
:::

## 레시피 한 줄의 계산: 가중합, 편향, 행렬 곱 {#neuron}

식당 주방의 레시피 카드에 이렇게 적혀 있습니다. "소금은 어른 1명당 3꼬집, 아이 1명당 1꼬집, 기본 1꼬집."

어른 2명과 아이 1명이 왔습니다. 소금은 3 × 2 + 1 × 1 + 1 = **8꼬집**입니다. 여기에 나온 숫자는 세 종류입니다.

- 주문 (2, 1)은 **입력**입니다. 손님이 정합니다.
- 1명당 꼬집 수 (3, 1)은 **가중치**(weight)입니다. 입력을 몇 배로 셀지 정합니다.
- 기본 1꼬집은 **편향**(bias)입니다. 손님이 몇 명이든 똑같이 더합니다.

입력과 가중치의 내적 2 × 3 + 1 × 1 = 7을 **가중합**이라고 합니다. 여기에 편향 1을 더해 8이 됩니다.

AI 안에는 이 계산을 하는 작은 부품이 엄청나게 많습니다. 부품 하나를 **뉴런**(neuron)이라고 합니다.

뉴런을 수없이 이어 붙인 것이 **신경망**(neural network)입니다.

가중치와 편향을 합쳐 **파라미터**(parameter)라고 합니다. 레시피 카드에 적힌 숫자들입니다.

계산 방법과 파라미터를 묶은 것이 **모델**(model)입니다. 카드 한 장이 통째로 모델인 셈입니다.

::: {.key}
"파라미터가 70억 개인 모델"은 카드에 숫자가 70억 개 적혀 있다는 말입니다. AI가 배우는 일, 곧 **학습은 이 숫자들을 고치는 일**입니다.
:::

모델 이름 끝에 붙은 `7B` 같은 글자가 이 숫자입니다. B는 10억(billion)이라서 `7B`는 70억 개입니다. 클수록 대체로 어려운 일을 잘하지만 파일이 크고 답이 느립니다([27장](ch27.html)).

실제로는 양념도 여러 가지, 주문도 여러 건입니다. 그래서 숫자를 표로 정리합니다.

::: {.fig src="matmul.svg"}
오른쪽 표의 한 칸은 가중합 한 번입니다.
:::

왼쪽 주문표 X에는 주문 A(어른 2, 아이 1)와 주문 B(어른 1, 아이 3)가 있습니다. 가운데 레시피표 W에는 고춧가루 칸이 생겼습니다. 어른 1명당 2꼬집, 아이 1명당 0꼬집입니다.

표의 가로줄은 행, 세로줄은 열입니다. 오른쪽 표의 한 칸은 X의 행 하나와 W의 열 하나를 같은 자리끼리 곱해 더한 값입니다. 주문 A의 소금은 A 행 (2, 1)과 소금 열 (3, 1)로 2 × 3 + 1 × 1 = 7입니다. 고춧가루는 A 행과 고춧가루 열 (2, 0)으로 2 × 2 + 1 × 0 = 4입니다.

이렇게 두 표로 새 표를 채우는 계산이 **행렬 곱**입니다. 그림의 XW는 X와 W를 행렬 곱했다는 표시입니다. 모양은 [주문 2, 사람 2] × [사람 2, 양념 2] → [주문 2, 양념 2]입니다. 맞닿은 '사람' 축의 칸 수가 같아야 곱할 수 있습니다.

이런 표 계산은 손으로 하지 않습니다. 숫자 표의 계산을 미리 만들어 둔 코드 묶음을 가져다 씁니다. 가장 널리 쓰는 것이 **NumPy**(넘파이)입니다. AI에게 숫자 계산을 부탁하면 이 이름이 자주 보입니다.

아래는 그림의 계산을 **파이썬**(Python)이라는 프로그래밍 언어에서 NumPy로 적은 코드입니다. `#` 뒤의 글은 사람이 읽으라고 적어 둔 메모(주석)입니다. 코드를 처음 본다면 [초코딩 기초](code.html)를 먼저 보세요.

```python
import numpy as np

X = np.array([[2, 1], [1, 3]])   # 주문표: 주문 A, 주문 B
W = np.array([[3, 2], [1, 0]])   # 레시피표: 어른 1명당, 아이 1명당
print(X.shape)                   # 모양
print(X @ W)                     # 행렬 곱
```

- 첫 줄: NumPy를 가져와서 `np`라는 짧은 이름으로 부릅니다.
- `X`와 `W` 줄: 그림의 두 표를 만듭니다. 안쪽 대괄호 하나가 행 하나입니다.
- `X.shape` 줄: X의 모양을 화면에 찍습니다.
- `X @ W` 줄: `@`가 행렬 곱입니다.

실행하면 이렇게 찍힙니다. 첫 줄이 모양으로, 행 2개에 열 2개입니다. 그 아래는 그림의 오른쪽 표와 같습니다.

```text
(2, 2)
[[7 4]
 [6 2]]
```

맞닿은 축의 칸 수가 다르면 NumPy는 오류를 내고 멈춥니다. 오류 글 끝의 `(size 2 is different from 3)`은 맞닿은 칸 수가 2와 3으로 다르다는 뜻입니다. 오류 글에 `shape`, `size`, `broadcast` 같은 낱말이 보이면 모양부터 확인합니다.

::: {.warn}
`*`는 행렬 곱이 아닙니다. `X * W`는 같은 자리끼리만 곱해서 6, 2, 1, 0이라는 다른 표를 냅니다. 오류 없이 돌아가서 알아채기 어렵습니다. AI가 쓴 코드에 `@`와 `*` 가운데 무엇이 쓰였는지 보세요.
:::

여기에 행마다 편향 (1, 0)을 더하면 신경망의 **층**(layer) 하나가 끝납니다. 소금에만 기본 1꼬집을 더한 것입니다. 소금 뉴런과 고춧가루 뉴런, 둘이 한 층입니다.

AI는 이 곱셈과 덧셈을 셀 수 없이 되풀이합니다. 같은 계산을 한꺼번에 많이 하는 GPU([1장](ch01.html))를 쓰는 까닭입니다.

## 직선만 쌓으면 직선: ReLU가 필요한 이유 {#relu}

층을 많이 쌓으면 더 똑똑해질 것 같습니다. 그런데 곱하고 더하기만 하는 층은 아무리 쌓아도 한 층과 같습니다.

첫 층은 "2를 곱하고 1을 더하기", 둘째 층은 "3을 곱하고 4를 더하기"라고 합시다. 1을 넣으면 3을 거쳐 13이 됩니다. 2를 넣으면 5를 거쳐 19가 됩니다. "6을 곱하고 7을 더하기" 한 층과 답이 똑같습니다. 6 × 1 + 7 = 13, 6 × 2 + 7 = 19입니다. 그래프로 그리면 직선 하나입니다. 백 층을 쌓아도 직선입니다.

하지만 세상일은 직선이 아닙니다. 소금은 넣을수록 맛있어지다가 어느 선을 넘으면 맛없어집니다. 이렇게 올라갔다 내려오는 모양은 직선으로 못 그립니다.

그래서 층 사이에 선을 꺾는 계산을 끼웁니다. 가장 많이 쓰는 것이 **ReLU**(렐루)입니다. 규칙은 한 줄입니다. **음수면 0으로 바꾸고, 양수면 그대로 둡니다.** "고춧가루 −1꼬집"이 나오면 0꼬집을 넣는 셈입니다. 이미 넣은 것을 덜어낼 수는 없으니까요.

선을 꺾는 이런 계산을 통틀어 **활성화 함수**(activation function)라고 합니다.

::: {.fig src="relu.svg"}
왼쪽: ReLU를 끼우면 선이 꺾입니다. 오른쪽: 꺾인 선 둘을 더하면 산 모양이 나옵니다.
:::

왼쪽 파란 선은 3 × ReLU(2x − 1)입니다. x는 넣는 숫자이고, 2x는 2 × x를 줄여 쓴 것입니다. x에 2를 곱하고 1을 뺀 값을 ReLU에 넣고, 3을 곱합니다.

- x = 0이면 2 × 0 − 1 = −1. 음수라서 0이 됩니다. 3 × 0 = 0
- x = 1이면 2 × 1 − 1 = 1. 그대로입니다. 3 × 1 = 3
- x = 2이면 2 × 2 − 1 = 3. 그대로입니다. 3 × 3 = 9

ReLU가 없었다면 x = 0에서 −3이 나왔을 것입니다. 회색 점선입니다. ReLU 덕분에 선이 x = 0.5에서 꺾였습니다.

꺾인 선 하나는 "여기서부터 켜지는 스위치"입니다. 오른쪽은 스위치 둘을 더한 ReLU(x) − 2 × ReLU(x − 1)입니다. 첫째 ReLU(x)는 x가 0을 넘으면 켜집니다. 둘째 ReLU(x − 1)은 x가 1을 넘어야 켜집니다.

x가 1보다 작을 때는 첫째만 켜져 올라갑니다. 1을 넘으면 둘째도 켜져 선을 끌어내립니다. x = 2에서는 2 − 2 × 1 = 0으로 돌아옵니다. 산 모양이 생겼습니다. 스위치가 수천 개면 구불구불한 모양도 흉내 낼 수 있습니다.

::: {.key}
신경망은 **곱하고 더하기 → 꺾기**를 되풀이한 것입니다. 꺾기를 빼면 전체가 직선 하나로 줄어듭니다.
:::

## 점수를 확률로, 확률을 벌점으로: 소프트맥스와 손실 {#softmax}

휴대전화 자판에 "오늘 점심은"까지 치면 다음 낱말이 추천으로 뜹니다. 이렇게 다음에 올 낱말을 맞히는 모델을 **언어 모델**이라고 합니다.

언어 모델은 후보마다 점수를 매깁니다. 김치찌개 2점, 된장국 1점, 미역국 0점이라고 합시다. 모델이 막 내놓은 이 점수를 **로짓**(logit)이라고 합니다. 코드에서는 `logits`라는 이름으로 자주 보입니다.

점수는 음수일 수도 있고 합도 제멋대로입니다. 그래서 "몇 %"인지 알려 주는 확률([13장](ch13.html))로 바꿉니다. 확률은 모두 0 이상이고 다 더하면 1입니다.

이 계산을 **소프트맥스**(softmax)라고 합니다. 세 걸음입니다.

1. 점수마다 "2.718을 점수만큼 거듭 곱한 값"을 구합니다. 2점은 2.718 × 2.718 ≈ 7.39입니다. 1점은 2.718 그대로이고, 짧게 2.72로 적습니다. 0점은 1로 약속합니다. ≈는 '약'이라는 뜻입니다.
2. 세 값을 더합니다. 11.11입니다.
3. 값마다 합으로 나눕니다. 김치찌개는 7.39 ÷ 11.11 ≈ 0.665입니다.

2.718…은 수학에서 자주 쓰는 수로, 이름이 e입니다. 그림의 'e의 점수 제곱'은 e를 점수만큼 거듭 곱했다는 뜻입니다.

점수가 음수여도 됩니다. −1점이면 1을 e로 한 번 나눈 0.37입니다. 어떤 점수든 0보다 큽니다.

::: {.fig src="softmax.svg"}
점수 (2, 1, 0)이 확률 (0.665, 0.245, 0.090)이 되는 과정. 오른쪽 끝은 그 후보가 정답이었을 때의 손실입니다.
:::

점수는 1점씩 차이인데 확률은 약 2.7배씩 벌어졌습니다.

### 틀린 정도를 숫자 하나로

모델을 고치려면 "얼마나 틀렸는지"를 숫자 하나로 알려 줘야 합니다. 이 벌점을 **손실**(loss)이라고 합니다.

여럿 가운데 하나를 고르는 문제에서는 **정답에 준 확률**만 봅니다.

**손실 = −ln(정답에 준 확률)**

ln은 '엘엔'이라고 읽습니다. "e를 몇 번 곱해야 이 수가 되는가"를 알려 주는 계산입니다. e를 2번 곱하면 7.39이니 ln 7.39는 2입니다. [9장](ch09.html)에서 본 로그와 같은 종류입니다. 1보다 작은 수를 넣으면 음수가 나오므로, 앞에 −를 붙여 양수로 뒤집습니다.

| 정답에 준 확률 | 1 | 0.5 | 0.1 | 0.01 |
|---|---|---|---|---|
| 손실 | 0 | 0.69 | 2.30 | 4.61 |

확률 1을 줬으면 벌점은 0입니다. 적게 줄수록 벌점이 가파르게 커집니다. **자신 있게 틀릴수록 크게 혼납니다.**

그림 오른쪽 끝이 이 손실입니다. 정답은 원-핫으로 적습니다. 된장국이 정답이면 (0, 1, 0)입니다. 1이 적힌 둘째 칸의 확률 0.245만 골라 −ln 0.245 ≈ 1.41을 구합니다. 확률을 가장 많이 준 김치찌개가 정답이었다면 0.41로 작습니다. 가장 적게 준 미역국이 정답이었다면 2.41로 큽니다.

이렇게 재는 손실을 **교차 엔트로피**(cross-entropy)라고 합니다. AI를 가르치는 코드에서 `CrossEntropyLoss` 같은 이름으로 만납니다.

숫자를 맞히는 문제에서는 더 쉬운 손실을 씁니다. 모델이 내놓은 답인 예측에서 정답을 빼고 제곱합니다. 다음 절에서 씁니다.

## 맛보고 조금 고치기: 기울기와 경사 하강 {#gradient}

::: {.analogy title="국 간 맞추기"}
요리사는 레시피대로 끓이고(예측), 맛을 봅니다(손실). 짠지 싱거운지 가늠해서(기울기) 레시피의 숫자를 조금 고칩니다. 한 번에 왕창 고치지 않고 **조금씩 여러 번** 합니다. 신경망의 학습도 이 네 박자를 되풀이합니다.
:::

레시피를 줄여 봅시다. "소금은 어른 1명당 w꼬집, 기본 1꼬집"입니다. w는 아직 정하지 못한 숫자에 붙인 이름입니다. 지금은 w = 3입니다.

어른 2명이 왔습니다. 소금은 3 × 2 + 1 = 7꼬집입니다. 맛을 보니 짭니다. 딱 좋은 양은 5꼬집이었습니다. 손실은 (7 − 5)² = 2 × 2 = 4입니다.

w를 올려야 할까요, 내려야 할까요? **조금 바꿔 보면** 압니다. w를 3.01로 올리면 소금은 7.02꼬집, 손실은 2.02 × 2.02 = 4.0804입니다.

w를 0.01 올렸더니 손실이 0.0804 올랐습니다. 올린 양의 약 8배입니다. 이 배율을 **기울기**(gradient)라고 합니다.

기울기 +8은 "w를 올리면 손실이 커진다"는 뜻입니다. 그러니 w를 **내려야** 합니다. 이렇게 기울기의 반대쪽으로 조금 움직이는 방법이 **경사 하강법**(gradient descent)입니다.

**새 w = 지금 w − 보폭 × 기울기**

보폭은 한 번에 얼마나 고칠지 정하는 숫자입니다. 정식 이름은 **학습률**(learning rate)입니다. 소금을 한 꼬집씩 넣느냐, 한 국자씩 넣느냐와 같습니다. 코드에서는 영어 이름을 줄여 `lr`이라고 적을 때가 많습니다. `lr=1e-3`의 `1e-3`은 0.001을 줄여 쓴 것입니다.

::: {.comic src="comic-gradient.webp"}
안개 낀 산에서는 골짜기가 보이지 않습니다. 발밑의 기울기로 낮아지는 쪽을 알아내 한 걸음 가고, 새 자리에서 다시 봅니다. 3번 칸의 점선처럼 걸음이 너무 크면 골짜기를 넘어가 버립니다.
:::

산의 높이가 손실, 서 있는 자리가 w입니다. 우리 숫자로 걸어 봅시다.

::: {.fig src="descent.svg"}
같은 기울기 +8에서 출발해도 보폭에 따라 결과가 갈립니다. 가장 낮은 곳은 소금이 딱 5꼬집이 되는 w = 2입니다.
:::

- 보폭 0.1: 새 w = 3 − 0.1 × 8 = 2.2. 소금 5.4꼬집, 손실 0.4 × 0.4 = 0.16. 크게 줄었습니다.
- 보폭 0.3: 새 w = 3 − 0.3 × 8 = 0.6. 소금 2.2꼬집, 손실 2.8 × 2.8 = 7.84. 싱거운 쪽으로 넘어가 오히려 커졌습니다.

한 걸음 뗀 뒤에는 **새 자리에서 기울기를 다시 구합니다.** w = 2.2에서는 기울기가 1.6입니다. 보폭 0.1로 한 번 더 가면 새 w = 2.2 − 0.1 × 1.6 = 2.04, 손실은 0.0064입니다. 골짜기에 가까울수록 기울기가 작아져 걸음도 저절로 줄어듭니다.

::: {.tip}
보폭 0.3으로 계속 걸으면 손실이 7.84, 15.4, 30.1로 걸음마다 커집니다. AI를 가르치는 코드가 찍는 손실이 이렇게 커지거나 `nan`(숫자가 아니라는 표시)이 되면 학습률이 너무 큰 것부터 의심합니다.
:::

::: {.key}
기울기는 **방향**을, 학습률은 **보폭**을 정합니다. 한 걸음 뗄 때마다 기울기를 새로 구합니다.
:::

::: {.try}
w = 2.2에서의 기울기를 계산기로 구해 보세요. w = 2.21이면 손실은 0.1764입니다. (0.1764 − 0.16) ÷ 0.01이 약 1.6인지 봅니다.
:::

## 어느 숫자 탓인가: 연쇄 법칙과 역전파 {#backprop}

방금은 w를 직접 바꿔 보고 기울기를 구했습니다. 파라미터가 70억 개면 70억 번을 바꿔 봐야 합니다. 더 빠른 길이 있습니다.

계산을 단계로 쪼갭니다. w에 2를 곱하고, 1을 더하고, 5를 빼고, 제곱합니다. 값은 3 → 6 → 7 → 2 → 4로 흘러갑니다. 예측 7에서 정답 5를 뺀 2를 오차라고 부릅시다.

단계마다 **배율**이 있습니다. 들어온 값이 1 커질 때 나가는 값이 커지는 양입니다.

- 2를 곱하는 단계: 배율 2
- 1을 더하는 단계, 5를 빼는 단계: 배율 1
- 제곱하는 단계: 배율 4. 오차 2를 2.01로 올리면 제곱은 4에서 4.0401이 됩니다. 0.01의 약 4배가 올랐습니다. 제곱 단계의 배율은 늘 들어온 값의 2배입니다.

전체 영향은 **배율을 모두 곱한 것**입니다. 2 × 1 × 1 × 4 = 8로, 앞에서 구한 기울기와 같습니다. 이 규칙이 **연쇄 법칙**(chain rule)입니다.

::: {.comic src="comic-chain-rule.webp"}
바늘 눈금판 세 개가 x → u → y로 이어져 있습니다. 맨 앞 손잡이를 돌리면 단계마다 정해진 배율(만화의 '변화율')로 다음 바늘이 움직입니다. 배율을 모두 곱하면 맨 앞 손잡이의 영향이 나옵니다.
:::

::: {.fig src="backprop.svg"}
윗줄은 앞으로 가며 구한 값, 아랫줄은 손실에서 거꾸로 돌아오며 구한 기울기입니다.
:::

아랫줄의 숫자는 "윗줄의 그 값을 1 올리면 손실이 얼마나 오르나"입니다. 손실 자신은 1 올리면 1 오릅니다. 그래서 오른쪽 끝의 1에서 출발합니다.

왼쪽으로 한 칸 갈 때마다 그 단계의 배율을 곱합니다. 1 × 4 = 4, 4 × 1 = 4, 4 × 1 = 4, 4 × 2 = 8입니다. 맨 왼쪽의 8이 w의 기울기입니다.

이렇게 **손실에서 출발해 배율을 곱하며 거꾸로 돌아오는 방법**이 **역전파**(backpropagation)입니다. 지나온 모든 칸의 기울기가 한꺼번에 나옵니다. 파라미터가 몇 개든 앞으로 한 번, 거꾸로 한 번이면 됩니다. 국이 짤 때 마지막에 넣은 것부터 거슬러 올라가며 "무엇 탓인가"를 따지는 것과 같습니다.

역전파도 사람이 직접 계산하지 않습니다. AI를 가르칠 때 널리 쓰는 파이썬 도구 **PyTorch**(파이토치)가 대신 합니다. PyTorch는 NumPy처럼 숫자 묶음을 계산하면서, 앞으로 가며 한 계산을 모두 적어 둡니다. 그래서 `loss.backward()` 한 줄이면 거꾸로 돌아오며 기울기를 모두 구합니다. backward는 '거꾸로'라는 뜻입니다.

그 뒤에 흔히 오는 `optimizer.step()`은 구한 기울기로 파라미터를 한 걸음 고치는 줄입니다. 이 두 줄이 보이면 학습하는 코드입니다.

## 여러 손님, 처음 온 손님: 미니배치와 과적합 {#generalize}

손님 한 명의 말만 듣고 레시피를 고치면 그 사람 입맛에 휘둘립니다. 그래서 주문 몇 건을 묶어 기울기의 **평균**을 내고 한 번 고칩니다. 이 묶음이 **미니배치**(mini-batch)입니다.

w = 3에서 두 건을 봅시다. 손님 A는 앞에서 본 손님입니다. 소금이 2꼬집 많았고 기울기는 +8입니다. "w를 줄여라"입니다.

손님 B는 어른 1명이고 딱 좋은 양이 6꼬집입니다. 넣은 소금은 3 × 1 + 1 = 4꼬집으로 2꼬집 모자랐습니다. 같은 방법으로 구한 기울기는 −4입니다. "w를 늘려라"입니다.

평균은 (8 − 4) ÷ 2 = +2입니다. 보폭 0.1이면 새 w = 3 − 0.1 × 2 = 2.8입니다.

### 외우기와 이해하기

문제집 한 권을 답까지 외운 친구가 있습니다. 그 문제집으로는 100점이지만 처음 보는 문제는 못 풉니다.

AI도 그럴 수 있습니다. 단골 열 명의 평가에만 레시피를 끝없이 맞추면 그들의 버릇까지 외워 버립니다. 처음 온 손님에게는 오히려 맛없는 국이 됩니다. 이 상태가 **과적합**(overfitting)입니다.

거꾸로 처음 보는 문제도 잘 푸는 힘을 **일반화**(generalization)라고 합니다. AI를 가르치는 목표는 외운 문제 100점이 아니라 일반화입니다.

그래서 배울 자료(데이터)를 둘로 나눕니다. 배우는 데 쓰는 **훈련 데이터**는 단골손님입니다.

배우는 데 쓰지 않고 채점만 하는 **검증 데이터**는 처음 온 손님입니다.

::: {.fig src="overfit.svg"}
훈련 손실은 계속 줄지만 검증 손실은 3단계 뒤에 다시 오릅니다. 골라야 할 모델은 3단계의 것입니다.
:::

훈련 데이터로 잰 훈련 손실은 0.8, 0.4, 0.2, 0.1로 계속 줄어듭니다. 검증 데이터로 잰 검증 손실은 0.9, 0.5, 0.45로 줄다가 4단계에서 0.6으로 오릅니다. 여기부터는 외우기입니다. 그래서 3단계에서 멈추고 그때의 모델을 씁니다.

실제로는 이 숫자들이 글자로 찍힐 때가 많습니다. 도구마다 조금씩 다르지만 대개 이런 줄입니다.

```text
epoch 1  train_loss 0.80  val_loss 0.90
epoch 2  train_loss 0.40  val_loss 0.50
epoch 3  train_loss 0.20  val_loss 0.45
epoch 4  train_loss 0.10  val_loss 0.60
```

`epoch`은 그림의 '단계'입니다. 훈련 데이터를 한 바퀴 다 본 것을 1**에포크**(epoch)라고 합니다. `train_loss`는 훈련 손실이고, `val_loss`는 검증(validation) 손실입니다. 두 숫자가 벌어지기 시작하는 줄을 찾습니다.

::: {.tip}
"손실이 0.01까지 내려갔어요"라는 말을 들으면 **어느 데이터로 잰 손실인지** 물어보세요. 훈련 손실만 낮은 모델은 문제집을 외운 친구와 같습니다.
:::

::: {.try}
위의 네 줄을 AI 챗봇에 붙여 넣고 "몇 번째 에포크의 모델을 골라야 해? 까닭도 말해 줘"라고 물어보세요. 3이라고 답하는지, 까닭에 검증 손실이 나오는지 봅니다.
:::

## 같은 재료로 만든 두 가지: 어텐션과 LoRA {#attention}

지금까지 본 계산만으로 요즘 AI의 중요한 부품 두 가지를 읽을 수 있습니다.

### 어텐션: 누구를 얼마나 참고할까

"찌개가 식어서 그것을 데웠다"에서 '그것'이 무엇인지 알려면 '찌개'를 봐야 합니다. AI는 이것을 계산으로 알아냅니다. **다른 낱말을 얼마나 참고할지 정해서 섞는 계산**을 **어텐션**(attention)이라고 합니다. 낱말마다 벡터 세 개를 씁니다.

- **쿼리**(Query, Q): "나는 이런 것을 찾는다"는 질문
- **키**(Key, K): "나는 이런 낱말이다"라는 이름표
- **값**(Value, V): 참고될 때 건네줄 내용

모둠 숙제를 할 때 내 궁금증과 이름표가 잘 맞는 친구의 공책을 더 많이 참고하는 것과 같습니다.

::: {.fig src="attention.svg"}
'그것'의 어텐션 계산. ① 질문과 키의 내적으로 점수를 내고 ② 소프트맥스로 비중을 만든 뒤 ③ 그 비중대로 값을 섞습니다.
:::

그림에서는 쿼리를 '질문 q', 키를 k, 값을 v로 적었습니다. q·k는 q와 k의 내적이라는 표시입니다.

1. '그것'의 질문 q = (1, 1)을 낱말마다 키와 내적합니다. '찌개'의 키 (2, 0)과는 1 × 2 + 1 × 0 = 2점입니다. '식어서'는 1점, '그것' 자신은 0점입니다.
2. 점수 (2, 1, 0)을 소프트맥스에 넣습니다. 앞에서 본 점수와 같으니 답도 (0.665, 0.245, 0.090)입니다. 낱말마다 참고할 비중입니다.
3. 값에 비중을 곱해서 더합니다. '찌개'는 0.665 × (4, 0) = (2.66, 0)입니다. 셋을 더하면 (2.84, 1.16)입니다.

'그것'의 새 벡터에 '찌개'의 내용이 가장 많이 섞였습니다.

이 부품으로 글 쓰는 AI를 만드는 이야기는 [27장](ch27.html)에서 이어집니다.

### LoRA: 큰 표를 작은 두 표로

이미 다 배운 큰 모델을 내 쓰임새에 맞게 조금 더 가르치는 일을 **파인튜닝**(fine-tuning)이라고 합니다. 우리말로 미세 조정이라고도 합니다. 가중치 표 하나가 가로세로 1000칸이면 고칠 숫자가 100만 개입니다.

그런데 "얼마나 고칠지"를 적은 표는 단순한 경우가 많습니다. 그림에서는 이 표를 변화량 표라고 적었습니다. 왼쪽 표는 16칸이지만, 네 행이 모두 V = (2, 0, 1, 1)의 1배, 2배, 0배, 3배입니다. 몇 배인지를 세로줄 U = (1, 2, 0, 3)에 적으면 8칸으로 줄어듭니다.

::: {.fig src="lora.svg"}
16칸짜리 표를 4칸 + 4칸으로 줄였습니다. 표가 클수록 더 많이 아낍니다.
:::

행들은 김치찌개와 육개장처럼 방향이 같고 길이만 다릅니다. 표 안에 서로 다른 방향이 몇 가지인지 세는 수가 **랭크**(rank)입니다. 이 표는 랭크 1입니다.

**LoRA**(로라)는 이 점을 씁니다. 원래 가중치 표는 그대로 두고, 작은 두 표 U와 V만 배워서 원래 표에 U × V를 더해 씁니다. 본점의 레시피 책은 건드리지 않고 메모 한 장만 덧붙이는 셈입니다. 랭크를 8로 잡으면 U와 V가 8줄씩입니다. 배울 숫자는 8 × (1000 + 1000) = 16,000개로, 100만 개의 1.6%입니다.

그림 그리는 AI에 화풍을 덧입히는 작은 파일이 흔히 이렇게 만든 것입니다.

## 고치는 날과 내는 날: 학습, 추론, 프롬프트 {#inference}

레시피를 다듬는 날과 손님에게 국을 내는 날은 다릅니다. 다듬는 날에는 맛보고 카드의 숫자를 고칩니다. 내는 날에는 카드에 적힌 대로 끓이기만 합니다.

AI도 같습니다. 예측하고, 손실을 재고, 기울기를 구해 파라미터를 고치기를 되풀이하는 일이 **학습**(training)입니다. 다 고친 파라미터로 앞으로만 계산해 답을 내는 일이 **추론**(inference)입니다. 챗봇에 질문할 때마다 일어나는 일은 추론입니다.

| | 학습 | 추론 |
|---|---|---|
| 파라미터 | 바뀐다 | 그대로 |
| 드는 힘 | 큰 모델은 GPU 수천 대로 몇 주 넘게 | 답 하나에 몇 초 |
| 누가 하나 | 대개 모델을 만드는 회사 | 챗봇이나 AI 기능을 쓰는 우리 |

### "학습시켰다"와 "프롬프트에 넣었다"

추론할 때 모델에 넣어 주는 글을 **프롬프트**(prompt)라고 합니다. 내 질문도, 챗봇에 붙인 파일도, AI 코딩 도구가 읽은 내 코드도 모두 프롬프트에 들어갑니다. 주문서에 메모를 붙인 것과 같습니다. 카드는 그대로이고, 대화가 끝나면 메모도 사라집니다.

그래서 "AI에게 우리 가게 메뉴를 학습시켰다"는 말은 두 가지 가운데 하나입니다.

| | 프롬프트에 넣기 | 파인튜닝 |
|---|---|---|
| 바뀌는 것 | 이번 입력 | 파라미터 |
| 준비물 | 넣을 글 | 잘 고른 예시 여러 건, 학습, 검증 |
| 알맞은 때 | 내 자료, 새 소식, 지킬 규칙 | 말투나 답하는 방식을 몸에 배게 할 때 |

내 자료를 AI가 알게 하고 싶다면 프롬프트에 넣는 쪽부터 해 봅니다. 자료가 많으면 질문에 맞는 부분만 찾아서 넣습니다([29장](ch29.html)). 파인튜닝은 그래도 안 될 때 꺼냅니다([27장](ch27.html)).

::: {.warn}
"우리 자료로 학습시킨 AI"라는 설명은 자료를 찾아 프롬프트에 넣는다는 뜻일 때가 많습니다. 거꾸로 AI에게 "내 자료를 학습시켜 줘"라고 하면 말 그대로 파인튜닝 코드를 짜기도 합니다. 어느 쪽인지 분명히 말하세요.
:::

::: {.try}
AI 챗봇에게 "우리 반 암호는 파란 김치찌개야"라고 알려 준 뒤 새 대화를 열어 암호를 물어보세요. 모른다면 암호는 프롬프트에만 있었고 파라미터는 그대로라는 뜻입니다. 맞힌다면 챗봇의 기억 기능이 그 말을 적어 두었다가 새 대화의 프롬프트에 다시 넣어 준 것입니다. 이때도 모델을 다시 학습시킨 것은 아닙니다.
:::

## 헷갈리기 쉬운 짝 {#pairs}

| 짝 | 차이 |
|---|---|
| 입력 / 가중치 | 손님이 정하는 주문 / 학습으로 고치는 레시피 숫자 |
| 내적 / 코사인 유사도 | 길이까지 넣은 값 / 길이를 지우고 방향만 견준 값 |
| 로짓 / 확률 | 어떤 수든 되는 점수 / 0 이상이고 다 더하면 1 |
| 손실 / 기울기 | 얼마나 틀렸나 / 어느 쪽으로 고치면 줄어드나 |
| 역전파 / 경사 하강법 | 기울기를 구한다 / 그 기울기로 숫자를 고친다 |
| 훈련 손실 / 검증 손실 | 풀어 본 문제의 점수 / 처음 보는 문제의 점수 |
| 학습 / 추론 | 파라미터를 고치는 일 / 고친 파라미터로 답을 내는 일 |
| 파인튜닝 / 프롬프트에 넣기 | 파라미터를 바꾼다 / 이번 입력에만 보탠다 |

## 실전 사례 {#case}

::: {.case title="닮은 국을 물었는데 늘 진한 국만 나온다"}
하은이는 AI의 도움을 받아 '닮은 국 찾기' 프로그램을 만들었습니다. 국마다 (짠맛, 매운맛)을 적어 두면, 고른 국과 가장 닮은 국을 알려 줍니다. 그런데 무엇을 골라도 부대찌개가 1등입니다.

1. **작은 예로 줄입니다.** 김치찌개 (3, 4)를 고르고, 후보는 육개장 (6, 8)과 부대찌개 (12, 5)만 남깁니다.
2. **점수를 손으로 구해 봅니다.** 화면에는 육개장 50점, 부대찌개 56점이 나와 있습니다. 3 × 12 + 4 × 5 = 56입니다. 내적을 그대로 쓰고 있었습니다.
3. **까닭을 찾습니다.** 내적은 진한 국일수록 커집니다. 부대찌개는 숫자가 통째로 큽니다.
4. **길이로 나눕니다.** 부대찌개의 길이는 13입니다(12 × 12 + 5 × 5 = 169 = 13 × 13). 코사인 유사도는 56 ÷ (5 × 13) ≈ 0.86입니다. 육개장은 1.0이니 이제 육개장이 1등입니다.
5. **답을 아는 질문으로 확인합니다.** 김치찌개끼리 견주면 1.0이 나와야 합니다.

계산이 틀린 것이 아니라 "닮았다"를 재는 자를 잘못 골랐습니다. 답이 이상하면 작은 예로 줄여 손으로 계산해 보세요.
:::

## 한눈에 정리 {#summary}

::: {.summary}
- AI 안에서는 무엇이든 숫자 목록인 **벡터**가 됩니다. 쌓으면 행렬과 텐서가 됩니다. **모양**의 축마다 무엇을 뜻하는지부터 확인합니다. 종류처럼 크기를 잴 수 없는 것은 **원-핫**으로 적습니다.
- **내적**은 같은 자리끼리 곱해 더한 값, **코사인 유사도**는 거기서 길이를 지운 값입니다. 뜻을 담은 **임베딩**을 이렇게 견주어 검색과 추천을 합니다.
- 뉴런은 **가중합 + 편향**, 층은 **행렬 곱**입니다. 사이를 **ReLU**로 꺾지 않으면 여러 층이 한 층과 같아집니다.
- **소프트맥스**는 점수(**로짓**)를 확률로, **손실**은 틀린 정도를 숫자 하나로 바꿉니다. 고르는 문제의 손실이 **교차 엔트로피**입니다.
- 학습은 맛보고 조금 고치기입니다. **기울기**의 반대쪽으로 **학습률**만큼 움직이고, 기울기는 **역전파**로 한꺼번에 구합니다.
- 표 계산은 **NumPy**가, 역전파는 **PyTorch**가 대신 해 줍니다.
- 모델은 훈련 손실이 아니라 **검증 손실**로 고릅니다. 목표는 처음 보는 문제도 잘 푸는 **일반화**입니다.
- **어텐션**은 내적 → 소프트맥스 → 비중대로 섞기입니다. **LoRA**는 고칠 양을 작은 두 표의 곱으로 배웁니다.
- **학습**은 파라미터를 고치고, **추론**은 고친 파라미터로 답을 냅니다. **프롬프트**에 넣은 글은 파라미터를 바꾸지 않습니다.
:::

## 확인 문제 {#quiz}

::: {.q}
라면의 맛을 (짠맛 4, 매운맛 3)이라고 적었습니다. 김치찌개 (3, 4)와의 내적과 코사인 유사도를 구해 보세요. 라면과 미역국(0.6) 가운데 어느 쪽이 김치찌개와 더 닮았을까요?

::: {.a}
내적은 3 × 4 + 4 × 3 = 24입니다. 라면의 길이는 4 × 4 + 3 × 3 = 25에서 5입니다. 코사인 유사도는 24 ÷ (5 × 5) = 0.96입니다. 0.6보다 크니 라면이 더 닮았습니다.
:::
:::

::: {.q}
분식집 떡볶이 레시피에 "고추장은 1인분당 2숟갈, 기본 1숟갈"이라고 적혀 있습니다. 3인분이면 고추장은 몇 숟갈일까요? 입력, 가중치, 편향은 각각 무엇일까요?

::: {.a}
2 × 3 + 1 = 7숟갈입니다. 손님이 정하는 3인분이 입력, 1인분당 2숟갈이 가중치, 늘 더하는 1숟갈이 편향입니다. 학습으로 고치는 것은 가중치와 편향입니다.
:::
:::

::: {.q}
샤워기 물이 차가워서 손잡이를 확 돌렸더니 너무 뜨겁습니다. 반대로 확 돌렸더니 이번에는 너무 차갑습니다. 경사 하강법으로 치면 무엇이 잘못되었을까요?

::: {.a}
방향은 맞는데 보폭, 곧 학습률이 너무 큽니다. 딱 좋은 온도를 번번이 건너뜁니다. 조금만 돌리고 다시 만져 봐야 합니다. 앞에서 본 보폭 0.3이 바로 이런 모습입니다.
:::
:::

::: {.q}
수학 문제집을 답까지 외운 친구가 그 문제집에서는 100점을 받고 학교 시험에서는 60점을 받았습니다. AI의 학습으로 치면 어떤 상태일까요? 어떻게 알아챌 수 있을까요?

::: {.a}
과적합입니다. 문제집은 훈련 데이터, 학교 시험은 검증 데이터와 같습니다. 학습에 쓰지 않는 검증 데이터를 떼어 두고 손실을 함께 잽니다. 훈련 손실은 주는데 검증 손실이 오르면 멈춥니다.
:::
:::

::: {.q}
분식집 사장님이 "AI 챗봇한테 우리 메뉴판을 학습시켰어"라고 합니다. 알고 보니 메뉴판 파일을 대화에 붙여 넣은 것이었습니다. 다음 날 새 대화를 열어 떡볶이 값을 물으면 어떻게 될까요? 왜 그럴까요?

::: {.a}
모른다고 하거나 그럴듯한 값을 지어냅니다. 파일을 붙인 것은 프롬프트에 넣은 것이라 그 대화에서만 보입니다. 파라미터는 바뀌지 않았으니 학습이 아닙니다. 새 대화에서는 메뉴판을 다시 넣어 줘야 합니다.
:::
:::

## AI에게 맡길 때 {#ai}

::: {.ai}
계산이 들어간 코드는 틀려도 오류 없이 숫자를 내놓습니다. 그래서 **답을 아는 작은 숫자**를 함께 주고, 그 값이 나오는지 돌려서 보여 달라고 합니다.

> 국의 맛을 (짠맛, 매운맛) 숫자 두 개로 적어 두고, 고른 국과 가장 닮은 국을 코사인 유사도로 찾아 주는 프로그램을 만들어 줘. 숫자 묶음마다 모양과 축의 뜻을 메모로 적어 줘. 내적과 길이 같은 중간 계산도 찍어 줘. 김치찌개 (3, 4)와 육개장 (6, 8)은 1.0, 김치찌개와 미역국 (5, 0)은 0.6이 나와야 해. 직접 돌려서 이 값이 나오는지 보여 줘.

**받은 답에서 확인할 것**

- 중간 계산에 내적 50과 15, 길이 5와 10이 찍혔는가.
- 내적을 두 길이로 나누는 줄이 있는가.
- 김치찌개끼리 견주면 1.0이 나오는가.
- 숫자 묶음마다 모양과 축의 뜻이 메모로 적혀 있는가.

**AI가 자주 하는 실수**

- **닮은 정도를 내적으로만 구합니다.** 무엇을 골라도 숫자가 큰 것이 1등이면 의심합니다. 벡터의 길이를 모두 1로 맞춰 두었을 때만 내적이 코사인 유사도와 같습니다.
- **`@` 자리에 `*`를 쓰거나 축의 순서를 바꿔 씁니다.** 오류가 나지 않습니다. 결과의 모양을 찍게 하고, 답을 아는 작은 표로 확인합니다.
- **"학습시켜 줘"를 말 그대로 받습니다.** 프롬프트에 넣으면 될 일에 파인튜닝 코드를 짭니다. 코드에 `loss.backward()`가 보이면 학습 코드입니다.
:::

## 용어 정리 {#terms}

::: {.terms}
벡터 (vector)
:   정해진 순서로 늘어놓은 숫자 목록.

원-핫 (one-hot)
:   종류마다 칸을 만들고 맞는 칸에만 1을 적는 방법.

스칼라 (scalar)
:   숫자 하나.

행렬 (matrix)
:   벡터를 여러 줄 쌓은 숫자 표.

텐서 (tensor)
:   숫자 표를 여러 장 겹친 묶음.

모양 (shape)
:   숫자 묶음의 축마다 칸이 몇 개인지 적은 것. 예: [2, 3, 2].

축 (axis)
:   숫자 묶음에서 칸을 세는 방향.

내적 (dot product)
:   두 벡터를 같은 자리끼리 곱해 모두 더한 값.

코사인 유사도 (cosine similarity)
:   내적을 두 벡터의 길이로 나눈 값. 방향이 같으면 1.

임베딩 (embedding)
:   낱말이나 글의 뜻을 담은 벡터.

차원 (dimension)
:   벡터의 칸 수.

입력 (input)
:   모델에 넣어 주는 숫자.

가중치 (weight)
:   입력을 몇 배로 셀지 정하는 숫자. 학습으로 고친다.

편향 (bias)
:   입력이 무엇이든 똑같이 더하는 숫자.

가중합 (weighted sum)
:   입력과 가중치의 내적.

뉴런 (neuron)
:   입력에 가중치를 곱해 더하고 편향을 더하는 작은 계산 부품.

신경망 (neural network)
:   뉴런을 수없이 이어 붙인 것.

파라미터 (parameter)
:   가중치와 편향처럼 학습으로 고치는 숫자 모두.

모델 (model)
:   계산 방법과 파라미터를 묶은 것.

행렬 곱 (matrix multiplication)
:   한 표의 행과 다른 표의 열을 내적해 새 표를 채우는 계산.

NumPy
:   숫자 표의 계산을 대신 해 주는 파이썬 코드 묶음.

층 (layer)
:   같은 입력을 받아 함께 계산하는 뉴런 한 줄.

ReLU (Rectified Linear Unit)
:   음수는 0으로 바꾸고 양수는 그대로 두는 계산.

활성화 함수 (activation function)
:   층 사이에 끼워 선을 꺾는 계산.

언어 모델 (language model)
:   다음에 올 낱말을 맞히는 모델.

로짓 (logit)
:   확률로 바꾸기 전에 모델이 내놓은 점수.

소프트맥스 (softmax)
:   점수 여러 개를, 다 더하면 1이 되는 확률로 바꾸는 계산.

손실 (loss)
:   예측이 정답에서 얼마나 벗어났는지 나타내는 숫자 하나.

교차 엔트로피 (cross-entropy)
:   정답에 준 확률에 −ln을 씌운 손실.

기울기 (gradient)
:   파라미터를 조금 올릴 때 손실이 그 몇 배만큼 움직이는지 나타내는 값.

경사 하강법 (gradient descent)
:   기울기의 반대쪽으로 파라미터를 조금씩 옮겨 손실을 줄이는 방법.

학습률 (learning rate)
:   한 번에 얼마나 고칠지 정하는 보폭.

연쇄 법칙 (chain rule)
:   단계마다의 배율을 모두 곱하면 전체 영향이 나온다는 규칙.

역전파 (backpropagation)
:   손실에서 거꾸로 돌아오며 모든 파라미터의 기울기를 구하는 방법.

PyTorch
:   숫자 묶음을 계산하고 역전파까지 대신 해 주는 파이썬 도구.

미니배치 (mini-batch)
:   기울기의 평균을 내려고 한 번에 묶어 보는 자료 몇 건.

과적합 (overfitting)
:   배운 문제는 잘 맞히지만 처음 보는 문제는 못 맞히는 상태.

일반화 (generalization)
:   처음 보는 문제도 잘 푸는 힘.

훈련 데이터 (training data)
:   배우는 데 쓰는 자료.

검증 데이터 (validation data)
:   배우는 데 쓰지 않고 채점에만 쓰는 자료.

에포크 (epoch)
:   훈련 데이터를 한 바퀴 다 본 것.

어텐션 (attention)
:   다른 낱말을 얼마나 참고할지 정해서 그 내용을 섞는 계산.

쿼리·키·값 (query, key, value)
:   어텐션에서 낱말마다 쓰는 세 벡터. 질문, 이름표, 건네줄 내용.

파인튜닝 (fine-tuning)
:   다 배운 모델을 내 쓰임새에 맞게 조금 더 가르치는 일.

랭크 (rank)
:   표 안에 서로 다른 방향이 몇 가지인지 세는 수.

LoRA (Low-Rank Adaptation)
:   원래 가중치는 그대로 두고 작은 두 표만 배워서 더하는 파인튜닝 방법.
:::

학습 (training)
:   손실이 줄도록 파라미터를 고쳐 가는 일.

추론 (inference)
:   다 고친 파라미터로 답을 계산해 내는 일.

프롬프트 (prompt)
:   추론할 때 모델에 넣어 주는 글.
