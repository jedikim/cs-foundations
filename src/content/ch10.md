::: {.lead}
게임에서 내 캐릭터의 체력, 가진 돈, 지금 있는 위치는 계속 바뀝니다. 프로그램은 이런 값을 기억하고 있어야 합니다. 프로그램이 기억하고 있는 값을 **상태**라고 합니다. 화면에는 돈이 100원이라고 나오는데 실제로는 50원이라면 곤란하겠죠. 많은 버그가 이렇게 상태가 꼬여서 생깁니다. 이 장에서는 상태가 꼬이지 않게 프로그램을 짜는 방법을 배웁니다.
:::

::: {.goals}
- 상태가 무엇이고 화면과 어떤 관계인지 말할 수 있습니다.
- 같은 정보를 한 곳에만 적어 두어야 하는 이유를 설명할 수 있습니다.
- 복사한 것을 고쳤는데 원래 것까지 바뀌는 이유를 설명할 수 있습니다.
- 프로그램이 있을 수 없는 상태에 빠지지 않게 하는 방법을 알 수 있습니다.
- AI가 만든 코드에서 뭉친 곳과 빠뜨린 화면을 찾아 고쳐 달라고 할 수 있습니다.
:::

## 상태: 프로그램이 기억하고 있는 것 {#state}

계산기에서 `2 + 3`을 누르면 언제나 5가 나옵니다.

분식집 주문 앱의 '담기' 버튼은 다릅니다. 김밥 옆의 '담기'를 한 번 누르면 김밥 1줄이 담깁니다. 한 번 더 누르면 2줄이 됩니다. 같은 버튼인데 결과가 다릅니다. 앱이 **앞에서 있었던 일을 기억하고 있기** 때문입니다.

이렇게 프로그램이 지금 기억하고 있는 것이 **상태**(state)입니다. 담아 둔 음식도, 입력 칸에 쓰다 만 글자도, "지금 불러오는 중"이라는 사실도 상태입니다.

::: {.analogy title="가게의 장부"}
분식집 계산대에는 주문을 적어 두는 장부가 한 권 있습니다. 직원은 장부를 보고 다음에 할 일을 정합니다. 장부가 틀리면 직원이 아무리 성실해도 가게는 틀리게 돌아갑니다. 지금부터 상태를 **장부**라고 부르겠습니다.
:::

화면은 장부를 보고 그린 그림입니다. 장부가 바뀌면 프로그램이 화면을 다시 그립니다. 사람이 버튼을 누르면 프로그램이 장부를 고칩니다.

::: {.fig src="state-screen.svg"}
왼쪽은 사용자, 곧 앱을 쓰는 사람이 보는 화면입니다. 오른쪽은 프로그램이 기억하는 상태입니다. 화면에 보이는 숫자가 모두 장부에 적혀 있지는 않습니다.
:::

왼쪽 화면의 '장바구니'는 담아 둔 음식의 목록입니다. 오른쪽 장부에는 칸이 세 개 있습니다. 칸 이름은 흔히 영어로 짓습니다.

- `items`에는 담은 음식이 적힙니다. 김밥 2줄과 떡볶이 1인분입니다.
- `coupon`에는 쓸 할인 쿠폰이 적힙니다. 지금은 없습니다.
- `status`에는 일이 어디까지 됐는지 적힙니다. 아직 주문 전이라 "대기"입니다.

장바구니 옆 빨간 동그라미 속의 숫자를 **배지**라고 합니다. 배지 3과 합계 10,500원은 장부에 없습니다. 2줄과 1인분을 더하면 3이고, 6,000원과 4,500원을 더하면 10,500원입니다. `items`만 있으면 계산할 수 있어서 따로 적지 않았습니다.

장부는 [1장](ch01.html)에서 본 메모리에 있습니다. 그래서 따로 저장하지 않으면 화면을 새로 고치거나 앱을 껐다 켤 때 사라집니다. 남아 있어야 하는 것은 AI에게 "새로 고침해도 남아 있어야 해"라고 말해 줍니다. 저장하는 곳은 [17장](ch17.html)에서 다룹니다.

장부에 한 줄이 잘못 적히면 한참 뒤에 엉뚱한 화면에서 말썽이 납니다. 장부가 꼬이는 길은 크게 네 가지입니다.

1. 같은 내용을 **두 군데에 적고** 한쪽만 고칩니다.
2. 아무나 장부를 **직접 고칩니다.**
3. "조리 중이면서 취소됨"처럼 **있을 수 없는 내용**이 적힙니다.
4. **늦게 도착한 소식**이 새 내용을 덮어씁니다.

이 네 가지를 막는 방법을 보기 전에, 프로그램의 기억이 어디에 들어 있는지부터 알아봅시다.

## 함수와 클로저: 기억은 어디에 있을까 {#function}

자판기에 돈을 넣고 버튼을 누르면 음료가 나옵니다. 안에서 무슨 일이 벌어지는지는 몰라도 됩니다.

프로그램에도 이런 자판기가 있습니다. 여러 줄의 일을 한 묶음으로 만들고 이름을 붙여 둔 것입니다. 이것을 **함수**(function)라고 합니다. 함수에게 일을 시키는 것을 "함수를 부른다"고 말합니다. 돈을 넣으면 음료가 나오듯, 함수에 값을 넣고 부르면 결과가 돌아옵니다.

함수는 일하는 동안 값을 잠깐 적어 둘 곳이 필요합니다. 값을 담아 두고 이름을 붙인 칸을 **변수**(variable)라고 합니다.

함수 안에서 만든 변수는 그 함수 안에서만 쓸 수 있습니다. 직원이 일하는 동안만 쓰고 버리는 메모지와 같습니다. 다른 직원은 그 메모지를 볼 수 없습니다. 이렇게 변수가 보이는 범위를 **스코프**(scope)라고 합니다.

스코프가 있어서 함수마다 같은 이름의 변수를 써도 서로 섞이지 않습니다. 대신 함수 밖에서 그 이름을 쓰면 흔히 `is not defined`라는 오류가 뜹니다. "그런 이름은 정해진 적이 없다"는 뜻입니다. 이 오류를 만나면 이름을 잘못 쳤는지, 스코프 밖에서 불렀는지 살펴보세요.

함수 밖에 만든 변수는 어느 함수에서나 보이고, 어디서나 고칠 수 있습니다. 이런 변수를 **전역 변수**(global variable)라고 합니다. 편해 보이지만, 값이 이상해졌을 때 누가 고쳤는지 찾기 어렵습니다. 아무나 고치는 장부가 되는 셈입니다. 그래서 변수는 그것을 쓰는 가장 좁은 범위에 만듭니다.

함수가 끝나면 메모지는 버려집니다. 그런데 메모지를 버리지 않고 들고 나오는 함수가 있습니다. 운동장을 몇 바퀴 돌았는지 셀 때 쓰는 계수기를 떠올려 봅시다. 누를 때마다 숫자가 1씩 오르는 작은 기계입니다. 아래는 **자바스크립트**(JavaScript)라는 프로그래밍 언어로 쓴 코드입니다. 계수기를 만들어 주는 함수입니다. 코드를 처음 본다면 [초코딩 기초](code.html)를 먼저 보세요.

```javascript
function makeCounter() {
  let n = 0;
  return () => ++n;
}
const a = makeCounter();
const b = makeCounter();
a(); a(); b();   // 차례로 1, 2, 1
```

- 1행은 `makeCounter`(계수기 만들기)라는 함수를 만듭니다. `{`부터 4행의 `}`까지가 이 함수가 하는 일입니다.
- 2행은 `n`이라는 변수를 만들고 0을 넣습니다. `let`은 변수를 만든다는 표시입니다.
- 3행의 `() => ++n`은 이름 없는 작은 함수입니다. 부르면 `n`을 1 늘려서 알려 줍니다. 이것이 계수기입니다. 앞의 `return`은 계수기를 밖으로 내보낸다는 뜻입니다.
- 5행과 6행은 `makeCounter`를 두 번 불러 계수기 `a`와 `b`를 만듭니다. `const`도 변수를 만든다는 표시입니다. 이름 뒤의 `()`는 그 함수를 부른다는 표시입니다.
- 7행은 `a`를 두 번, `b`를 한 번 누릅니다. 돌아오는 값은 차례로 1, 2, 1입니다. `//` 뒤의 글은 사람이 읽으라고 적어 둔 메모입니다. 이런 메모를 주석이라고 하고, 컴퓨터는 건너뜁니다.

`makeCounter`는 계수기를 내보내고 끝납니다. 보통이라면 메모지 `n`도 이때 버려집니다. 하지만 계수기가 `n`을 계속 써야 해서 `n`은 사라지지 않습니다. 이렇게 **자기가 만들어진 곳의 변수를 붙잡고 있는 함수**를 **클로저**(closure)라고 합니다.

::: {.fig src="closure-counters.svg"}
`makeCounter`를 부를 때마다 `n`이 새로 하나씩 생깁니다. `a`와 `b`는 서로의 `n`을 볼 수 없습니다.
:::

그림에서 `a`는 두 번 눌러 `n`이 2이고, `b`는 한 번 눌러 `n`이 1입니다. 계수기마다 자기 숫자를 따로 가집니다. 이 `n`은 밖에서 직접 고칠 수 없고, 계수기를 눌러야만 바뀝니다. 클로저는 상태를 숨겨 두는 작은 금고인 셈입니다.

### 계산만 하는 함수, 바깥을 바꾸는 함수

함수 가운데에는 계산만 하는 함수가 있습니다. 아래 그림의 `total`(합계)은 음식값을 받아 모두 더합니다. 6,000원과 4,500원을 넣으면 10,500원이 나옵니다. 그림의 `[6000, 4500]`은 두 값을 묶은 목록입니다. 같은 것을 넣으면 언제나 같은 값이 나오고, 장부는 건드리지 않습니다. 이런 함수를 **순수 함수**(pure function)라고 합니다.

자기 바깥의 무언가를 바꾸는 함수도 있습니다. 그림의 `totalAndPay`(합계 내고 결제하기)는 합계를 내면서 결제 요청도 보냅니다. 결제 요청은 "10,500원을 받아 주세요" 하는 부탁입니다. 이 부탁은 돈을 다루는 컴퓨터인 결제 서버로 갑니다. 이렇게 함수가 바깥을 바꾸는 일을 **부수 효과**(side effect)라고 합니다. 화면 바꾸기와 파일에 저장하기도 부수 효과입니다.

::: {.fig src="pure-vs-effect.svg"}
순수 함수는 몇 번을 불러도 바깥이 그대로입니다. 부수 효과가 있는 함수는 부른 횟수만큼 바깥이 바뀝니다.
:::

부수 효과가 나쁜 것은 아닙니다. 저장도 주문도 못 하는 앱은 쓸모가 없습니다. 문제는 **계산만 하는 줄 알았던 함수에 부수 효과가 숨어 있을 때**입니다. 합계만 알고 싶어서 `totalAndPay`를 두 번 부르면 돈이 두 번 빠져나갑니다.

::: {.key}
계산은 순수 함수로 합니다. 바깥을 바꾸는 일은 눈에 잘 띄는 한곳에 모읍니다.
:::

`totalAndPay`는 이름부터 두 가지 일을 합니다. `total`과 `pay`(결제하기)로 나누면 합계는 몇 번이든 마음 놓고 볼 수 있습니다. AI가 준 함수 이름에 '그리고'(And)가 들어 있다면 **한 가지 일만 하는 함수**로 나눠 달라고 하세요.

## 객체와 인터페이스: 장부는 창구로만 고칩니다 {#object}

주문 앱의 장바구니에는 규칙이 있습니다. 같은 음식을 또 담으면 새로 적지 않고 수량을 합칩니다. 수량은 1 이상이어야 합니다.

이 앱에는 음식을 담는 버튼이 셋 있습니다. '담기', 지난번 주문을 그대로 담는 '다시 담기', 추천 메뉴를 담는 '추천 담기'입니다. 세 버튼이 저마다 장바구니 목록을 직접 고친다고 해 봅시다. 한 버튼이라도 규칙을 잊으면 김밥이 두 번 따로 적히고, 수량이 0인 떡볶이가 생깁니다.

그래서 목록을 고치는 길을 하나로 모읍니다. `addItem`(하나 담기)이라는 함수를 만들고 규칙을 그 안에 적습니다. 세 버튼은 목록을 직접 건드리지 않고 `addItem`에게 부탁합니다. 장부를 창구 안쪽에 두고 창구 직원만 적게 하는 것과 같습니다.

::: {.fig src="cart-gate.svg"}
직접 고치게 두면 규칙을 어긴 줄이 섞여 듭니다. 창구를 하나로 모으면 규칙을 한 곳에만 적어도 됩니다. 그림의 '상품'은 여기서 음식을 말합니다.
:::

그림 위쪽의 `cart.items.push(…)`는 "장바구니(`cart`)의 목록(`items`)에 한 줄을 바로 밀어 넣어라"라는 코드입니다. 아래쪽의 `cart.addItem(…)`은 "장바구니야, 이것을 담아 줘"라는 코드입니다. 아래쪽에서는 김밥이 3으로 합쳐졌고, 수량이 0인 줄도 없습니다.

이렇게 데이터와 그 데이터를 고치는 함수를 한 묶음으로 만든 것을 **객체**(object)라고 합니다. 여기서는 목록과 `addItem`을 묶은 장바구니가 객체입니다.

객체 안쪽의 데이터는 숨겨 두고, 정해 둔 함수로만 고치게 하는 것을 **캡슐화**(encapsulation)라고 합니다. 알약의 캡슐이 가루를 감싸듯 안쪽을 감싸 둔다는 뜻입니다. 규칙을 `addItem` 한 곳에만 적으면 되고, 규칙을 어긴 줄이 들어올 길도 없어집니다. 앞에서 계수기가 `n`을 숨기고 누르는 것만 받아 준 것도 캡슐화입니다.

밖에서 쓸 수 있게 열어 둔 창구의 목록과 약속은 **인터페이스**(interface)라고 합니다.

::: {.analogy title="콘센트"}
벽의 콘센트는 구멍 모양과 전기의 세기만 약속합니다. 약속만 맞으면 선풍기든 충전기든 꽂아 쓸 수 있습니다. 벽 속의 전선을 바꿔도 선풍기는 그대로 씁니다. 장바구니도 `addItem`이라는 약속만 지키면, 안쪽을 바꿔도 버튼 쪽은 고칠 것이 없습니다.
:::

### 약속에는 '없음'과 '실패'도 적습니다

도서관 검색 컴퓨터에서 책을 찾았는데 아무것도 나오지 않습니다. 그 책이 없는 걸까요, 컴퓨터가 고장 나서 못 찾은 걸까요? 책이 없다면 다른 책을 고르면 됩니다. 고장이라면 잠시 뒤 다시 찾아봐야 합니다.

둘을 똑같이 빈 화면으로 보여 주면, 고장인데도 "그런 책은 없습니다"라고 말하는 셈입니다. **없음은 정상 결과이고, 실패는 사고입니다.** 그래서 함수가 결과에 '찾음', '없음', '실패' 같은 이름표를 붙여 내놓게 합니다.

### 틀 하나로 여러 개 찍어 내기: 클래스

붕어빵 가게는 틀 하나로 붕어빵을 몇 개든 찍어 냅니다. 프로그램에서도 같은 모양의 객체가 여러 개 필요할 때가 많습니다. 게임에 슬라임이라는 몬스터가 세 마리 나온다면 슬라임 객체도 셋이 있어야 합니다.

그래서 객체를 찍어 내는 틀을 먼저 만듭니다. 이 틀을 **클래스**(class)라고 합니다. 슬라임 클래스에는 슬라임이 가진 것과 할 줄 아는 일을 적어 둡니다. "체력을 적는 칸이 있고, 맞으면 체력이 1 줄어든다"는 식입니다.

틀로 찍어 낸 객체 하나하나는 **인스턴스**(instance)라고 합니다. 슬라임 세 마리는 할 줄 아는 일이 같지만, 체력은 저마다 따로 가집니다. 한 마리를 때려도 나머지 둘의 체력은 그대로입니다. 계수기 `a`와 `b`가 `n`을 따로 가졌던 것과 같습니다.

코드에서 `class`로 시작하는 묶음을 만나면 "객체를 찍어 낼 틀이구나" 하고 읽으면 됩니다.

### 물려받기와 끼워 넣기: 상속과 조합

게임에 박쥐도 나옵니다. 박쥐도 슬라임처럼 체력이 있고, 맞으면 체력이 줄어듭니다. 같은 내용을 두 클래스에 따로 적으면 고칠 때도 두 번 고쳐야 합니다.

첫째 방법은 물려받기입니다. 겹치는 내용을 '몬스터'라는 클래스에 한 번만 적습니다. 슬라임과 박쥐 클래스는 몬스터의 것을 통째로 물려받고, 저마다 다른 점만 더 적습니다. 이것을 **상속**(inheritance)이라고 합니다.

상속은 갈래가 섞일 때 막힙니다. '하늘을 나는 몬스터'와 '헤엄치는 몬스터'로 나누어 물려받게 했는데, 날기도 하고 헤엄도 치는 오리가 필요해졌다고 해 봅시다. 물려받을 곳은 보통 하나만 고를 수 있습니다. 어느 쪽을 골라도 다른 쪽 기능은 다시 적어야 합니다.

둘째 방법은 끼워 넣기입니다. '날기'와 '헤엄치기'를 작은 부품으로 따로 만들고, 필요한 몬스터에 골라 끼웁니다. 오리에게는 두 부품을 모두 끼우면 됩니다. 이것을 **조합**(composition)이라고 합니다. [24장](ch24.html)에서 볼 게임 만드는 도구도 이렇게 부품을 끼워 캐릭터를 만듭니다.

겹치는 코드를 줄이려는 것뿐이라면 상속보다 조합을 먼저 떠올리세요.

## 원본은 한 곳에: 주인과 파생 값 {#owner}

교실 칠판에 "우리 반 25명"이라고 적혀 있습니다. 전학생이 와서 출석부에는 이름을 올렸는데, 칠판 숫자는 아무도 고치지 않았습니다. 출석부는 26명이고 칠판은 25명입니다. 같은 내용을 두 군데에 적으면 이렇게 어긋납니다.

주문 앱에서도 같은 일이 생깁니다. 장바구니에 김밥, 떡볶이, 순대를 하나씩 담았습니다. 목록은 세 줄이고 배지는 3입니다. 순대를 지우자 2가 됐습니다. '삭제 취소'를 눌러 순대를 되살렸는데 배지는 그대로 2입니다.

프로그램 안을 들여다보니 음식 목록 `items`와 개수 `count`를 따로 적어 두고 있었습니다. 담을 때도 지울 때도 둘을 함께 고쳤습니다. 그런데 '삭제 취소'를 나중에 만들면서 `count`를 되돌리는 줄을 빠뜨렸습니다.

::: {.fig src="derived-drift.svg"}
같은 내용을 두 번 적으면, 고치는 곳 가운데 하나만 빠뜨려도 둘이 어긋납니다.
:::

그림 맨 아랫줄의 `items.length`는 "목록의 길이", 곧 목록을 그때그때 세어 본 값입니다. 이 값은 3, 2, 3으로 늘 목록과 맞습니다.

이렇게 **다른 상태에서 계산하면 나오는 값**을 **파생 값**(derived value)이라고 합니다. 개수도 합계도 파생 값입니다. 파생 값은 적어 두지 않고 필요할 때마다 계산합니다. 그러면 어긋날 수가 없습니다.

::: {.key}
같은 내용은 한 곳에만 적습니다. **계산하면 나오는 것은 따로 적어 두지 않습니다.**
:::

개수만 그런 것이 아닙니다. 게시판 댓글마다 글쓴이의 별명을 복사해 넣었다고 해 봅시다. 별명을 바꾸면 그 사람의 댓글을 모두 찾아 고쳐야 합니다. 그래서 댓글에는 "7번 회원"처럼 [8장](ch08.html)에서 배운 ID만 적습니다. 보여 줄 때 7번 회원의 별명을 읽어 옵니다. 별명이 적힌 곳이 하나뿐이니 고칠 곳도 하나입니다.

"이것이 진짜"라고 정해 둔 한 곳을 **원본**(source of truth)이라고 합니다. 원본마다 **주인**을 하나만 둡니다. 주인만 그 값을 고치고, 나머지는 읽기만 하거나 주인에게 고쳐 달라고 부탁합니다.

::: {.tip title="새로 고침하면 맞게 나온다면"}
숫자가 어긋나 있다가 새로 고침을 하면 맞게 나올 때가 있습니다. 같은 값이 두 군데에 적혀 있고 한쪽만 고쳐졌다는 신호입니다. 새로 고침을 하면 모든 값을 원본에서 다시 받아 와서 그때만 맞습니다. AI에게 물어보세요. "이 값의 원본은 어디야? 같은 값을 따로 적어 둔 곳을 모두 찾아 줘."
:::

## 복사했는데 같이 바뀐다: 얕은 복사 {#copy}

메신저의 프로필 고치기 화면을 떠올려 봅시다. 이름을 바꾸다가 '취소'를 누르면 원래대로 돌아가야 합니다. 그래서 프로그램은 원래 프로필을 복사해 연습장을 만듭니다. 이 연습장을 초안이라고 합니다. 고칠 때는 초안만 바꾸고, '취소'를 누르면 초안만 버립니다.

그런데 취소했는데도 원래 프로필이 바뀌어 있는 일이 생깁니다. 자바스크립트 코드로 적으면 이렇습니다.

```javascript
const original = { name: "하늘", tags: ["업무"] };
const draft = { ...original };   // 칸들을 새 상자에 옮겨 담는다
draft.name = "바다";             // 원본은 그대로 "하늘"
draft.tags.push("긴급");         // 원본의 tags도 바뀐다
```

- 1행은 원래 프로필 `original`(원본)을 만듭니다. `name`(이름) 칸에는 "하늘"이, `tags`(꼬리표) 칸에는 꼬리표 목록이 들어 있습니다. 꼬리표는 프로필에 붙이는 짧은 낱말이고, 지금은 "업무" 하나입니다.
- 2행은 초안 `draft`를 만듭니다. `{ ...original }`은 "원본의 칸들을 새 상자에 옮겨 담아라"라는 뜻입니다.
- 3행은 초안의 이름을 "바다"로 갈아 끼웁니다. 원본의 이름은 그대로입니다.
- 4행은 초안의 꼬리표 목록에 "긴급"을 밀어 넣습니다. 그런데 원본의 목록에도 "긴급"이 생깁니다.

왜 목록만 같이 바뀔까요? 꼬리표 목록은 [8장](ch08.html)에서 배운 배열입니다. [3장](ch03.html)에서 본 것처럼, 칸에는 배열 자체가 아니라 **배열이 있는 곳을 적은 쪽지**가 들어 있습니다. 2행은 이 쪽지만 옮겨 적었습니다. 그래서 원본과 초안이 **같은 배열**을 가리킵니다. 4행은 쪽지를 따라가 하나뿐인 배열에 "긴급"을 넣은 것입니다.

사물함 번호를 적은 쪽지를 친구에게 베껴 준 것과 같습니다. 쪽지는 두 장이지만 사물함은 하나입니다.

이렇게 겉만 새로 만들고 안쪽은 함께 쓰는 복사를 **얕은 복사**(shallow copy)라고 합니다.

안쪽까지 전부 새로 만드는 복사는 **깊은 복사**(deep copy)라고 합니다.

::: {.fig src="shallow-copy.svg"}
얕은 복사는 안쪽 배열을 함께 씁니다. 고칠 부분까지 따로 복사해야 초안이 원본에서 떨어져 나옵니다.
:::

그림 오른쪽이 고친 모습입니다. `tags: [...original.tags]`는 "꼬리표 배열도 새로 만들어 내용을 옮겨 담아라"라는 뜻입니다. 이제 배열이 둘이라서 초안에 "긴급"을 넣어도 원본에는 "업무"만 남습니다.

누가 "복사했다"고 말하면 **어디까지 따로이고 어디부터 함께 쓰는지** 물어보세요. AI가 준 코드에서 `{ ...original }`처럼 점 세 개로 한 복사는 겉 한 겹만 새로 만든 것입니다.

::: {.try}
컴퓨터의 브라우저에서 `F12`(맥은 `Cmd + Option + I`)를 누르고 Console 탭을 엽니다. 코드를 바로 쳐 볼 수 있는 곳입니다. 앞의 코드 네 줄을 넣고 Enter를 누른 다음 `original.tags`라고 쳐 보세요. "긴급"이 들어 있나요? 붙여 넣을 때 브라우저가 경고를 띄울 수 있습니다. 모르는 코드를 넣지 말라는 경고입니다. 이 네 줄은 뜻을 아는 코드이니 안내대로 허용합니다.

이번에는 `const draft2 = structuredClone(original)`이라고 칩니다. `structuredClone`은 안쪽까지 복사해 주는 함수입니다. `draft2.tags.push("새것")`을 한 뒤 `original.tags`를 다시 보세요. "새것"이 없으면 둘이 떨어진 것입니다.
:::

## 고치지 말고 새로 쓰기: 불변 업데이트와 실행 취소 {#immutable}

게임을 늘 같은 칸에 덮어서 저장하면 예전으로 돌아갈 수 없습니다. 저장할 때마다 새 칸을 쓰면 언제든 예전 저장을 불러올 수 있습니다.

프로그램의 상태에도 이 규칙을 씁니다. **한 번 만든 값은 고치지 않습니다.** 바꿀 일이 생기면 바뀐 내용으로 **새 값을 만들어 통째로 갈아 끼웁니다.** 이것을 **불변 업데이트**(immutable update)라고 합니다. '불변'은 변하지 않는다는 뜻입니다. 장부로 치면 지우개를 쓰지 않고 새 쪽에 다시 적는 것입니다.

프로필의 이름을 "바다"로 바꿀 때도 원래 프로필에는 손대지 않습니다. 이름만 "바다"인 새 프로필을 만듭니다. 좋은 점이 두 가지 있습니다.

- 옛 값을 쓰던 다른 곳이 **몰래 바뀐 값**에 속지 않습니다.
- 옛 쪽이 남아 있으니 **되돌리기**가 쉽습니다.

이 규칙을 꼭 지켜야 하는 곳도 있습니다. 화면을 만드는 도구 가운데에는(예: React) 상태가 **새 값으로 갈아 끼워졌을 때만** 화면을 다시 그리는 것이 있습니다. 이런 도구에서 목록에 `push`로 한 줄을 밀어 넣기만 하면, 도구는 바뀐 줄 모릅니다. 장부는 바뀌었는데 화면은 그대로입니다. 버튼을 눌러도 화면이 안 바뀌다가 다른 곳을 건드려야 바뀐다면, AI에게 "상태를 직접 고친 곳이 있는지 찾아 줘"라고 말해 보세요.

### 실행 취소: 과거, 현재, 미래 세 칸

그림 그리는 앱에서 '되돌리기'를 누르면 방금 그은 선이 사라집니다. 이 기능을 **실행 취소**(undo)라고 합니다. 옛 쪽이 남아 있다면 옛 쪽을 다시 펼치기만 하면 됩니다.

값을 과거, 현재, 미래 세 칸에 나눠 담습니다. 프로필 이름을 "하늘"에서 "바다"로, 다시 "구름"으로 고쳤다고 해 봅시다.

1. 고칠 때마다 그전의 현재를 과거 칸에 넣습니다. 지금 과거에는 "하늘"과 "바다"가, 현재에는 "구름"이 있습니다. 미래 칸은 비어 있습니다.
2. 실행 취소를 누르면 과거의 맨 뒤에 있던 "바다"가 현재가 됩니다. 밀려난 "구름"은 미래 칸으로 갑니다.
3. 여기서 '다시 실행'을 누르면 "구름"이 현재로 돌아옵니다.
4. 다시 실행 대신 이름을 "노을"로 새로 고치면 미래 칸의 "구름"은 버립니다.

::: {.fig src="undo-history.svg"}
첫 줄은 이름을 하늘에서 바다로, 다시 구름으로 고친 뒤의 세 칸입니다. 취소한 다음 새로 고치면 미래 칸에 있던 것은 버립니다.
:::

::: {.warn title="장부 밖의 일은 취소되지 않습니다"}
실행 취소가 되돌리는 것은 프로그램 안의 상태뿐입니다. 이미 낸 돈은 되돌리기 버튼으로 돌아오지 않습니다. 환불처럼 **반대 방향의 일을 새로 해야** 합니다.
:::

## 상태 기계: 있을 수 없는 상태를 못 만들게 {#machine}

신호등에는 빨강, 노랑, 초록 불이 있습니다. 불마다 스위치가 따로 달려 있다면 빨강과 초록을 한꺼번에 켤 수도 있습니다.

프로그램에서도 같은 일이 생깁니다. '저장' 버튼을 눌렀더니 빙글빙글 도는 표시와 "저장 완료"와 "오류"가 한꺼번에 떴습니다. 코드에는 참·거짓 값이 세 개 있었습니다. 참·거짓 값은 켜짐과 꺼짐만 있는 스위치와 같습니다. 세 스위치의 이름은 '로딩'(저장하는 중), '성공', '오류'였습니다.

스위치 세 개로 만들 수 있는 조합은 2 × 2 × 2 = 8가지입니다. 말이 되는 것은 네 가지뿐입니다.

- 셋 다 꺼짐: 대기
- 로딩만 켜짐: 저장 중
- 성공만 켜짐: 완료
- 오류만 켜짐: 오류

나머지 네 가지는 둘 이상이 함께 켜진 조합입니다. 스위치를 끄는 코드를 한 줄만 빠뜨려도 이런 조합이 생깁니다.

해결 방법은 상태를 **이름 하나**로 적는 것입니다. `status` 칸 하나에 "대기", "저장 중", "완료", "오류" 가운데 하나만 적습니다. 칸이 하나뿐이니 두 가지가 한꺼번에 적힐 수 없습니다.

여기에 무슨 일이 생기면 어느 상태로 넘어가는지도 정해 둡니다. 이렇게 **가능한 상태의 목록**과 **상태 사이를 넘어가는 길**을 정해 둔 것을 **상태 기계**(state machine)라고 합니다.

::: {.fig src="state-machine.svg"}
참·거짓 세 개는 있으면 안 되는 조합까지 만들어 냅니다. 이름 하나로 적으면 화살표로 이어진 길만 갈 수 있습니다.
:::

그림 오른쪽을 봅시다. 대기에서 저장을 누르면 저장 중이 됩니다. 성공하면 완료로, 실패하면 오류로 갑니다. 오류에서 '다시 시도'를 누르면 저장 중으로 돌아갑니다. 화살표가 없는 길로는 갈 수 없습니다. 받은 데이터는 완료일 때만, 실패한 이유는 오류일 때만 함께 적어 둡니다.

넘어가는 규칙은 코드 여기저기에 흩어 두지 않고 한곳에 모아 적습니다. 그림에 화살표가 없는 일은 무시합니다. 저장 중에 저장 버튼을 또 누르는 화살표는 없습니다. 그래서 눌러도 아무 일도 생기지 않습니다. 버튼을 빠르게 두 번 눌러 두 번 저장되는 버그가 사라집니다.

AI가 준 코드에서 `isLoading`(불러오는 중인가), `isError`(오류인가)처럼 `is`로 시작하는 참·거짓 값을 저마다 따로 켜고 끈다면, 앞에서 본 스위치들입니다. `status` 하나로 바꿔 달라고 하세요.

### 화면마다 네 가지 모습을 준비합니다

게시판처럼 목록을 불러와 보여 주는 화면에도 상태가 있습니다. 이런 화면은 네 가지 모습을 모두 갖춰야 합니다.

| 상태 | 화면에 보여 줄 것 |
|---|---|
| 불러오는 중 | 기다리라는 표시 |
| 성공 | 받아 온 목록 |
| 비어 있음 | "아직 글이 없습니다" 같은 안내 |
| 실패 | 무엇이 잘못됐는지와 '다시 시도' 버튼 |

AI에게 화면을 맡기면 '성공'만 만들어 줄 때가 많습니다. 그러면 불러오는 동안에는 흰 화면이 나옵니다. 실패하면 도는 표시가 끝없이 돌거나, 도서관 컴퓨터처럼 고장인데도 빈 목록을 보여 줍니다. 그래서 화면을 맡길 때는 "불러오는 중, 비어 있음, 실패일 때의 화면도 만들어 줘"라고 덧붙입니다.

::: {.try}
자주 쓰는 앱에서 네 가지 모습을 찾아보세요. 검색창에 아무 글자나 길게 쳐서 '비어 있음' 화면을 봅니다. 휴대전화를 비행기 모드로 바꾸고 다른 화면을 열어 '실패' 화면을 봅니다. 무엇이 잘못됐는지, 다시 해 볼 버튼이 있는지 살펴보세요. 끝나면 비행기 모드를 끕니다.
:::

## 바뀌면 알려 주기: 구독과 뒷정리 {#subscribe}

유튜브 채널을 구독하면 새 영상이 올라올 때마다 알림이 옵니다. 채널 주인은 구독자를 한 명씩 찾아다니지 않습니다. 영상을 올리면 명단의 모두에게 알림이 갑니다.

주문 앱도 이 방법을 씁니다. 장바구니가 바뀌면 배지도, 합계도, 주문 버튼도 다시 그려야 합니다. 장바구니가 셋을 하나하나 챙기는 대신 명단을 하나 둡니다.

배지는 "장바구니가 바뀌면 이 함수를 불러 주세요" 하고 명단에 함수를 올립니다. 이것을 **구독**(subscribe)이라고 합니다.

장바구니는 바뀔 때마다 명단의 함수를 모두 부릅니다. 이것을 **발행**(publish)이라고 합니다. 장바구니는 누가 듣는지 몰라도 됩니다.

함정이 하나 있습니다. **명단에서 이름을 빼는 일은 저절로 되지 않습니다.** 화면을 열 때 구독했다면 닫을 때 구독을 해제해야 합니다. 해제하지 않으면 닫힌 화면의 함수가 명단에 남고, 다시 열면 하나가 더 올라갑니다.

::: {.fig src="subscribe-leak.svg"}
열 때마다 구독하고 닫을 때 해제하지 않으면, 세 번째로 열었을 때는 음식을 한 번 담아도 배지를 세 번 다시 그립니다.
:::

그림의 윗줄은 해제하지 않은 경우입니다. 화면을 열고 닫을 때마다 명단의 구독이 1, 1, 2, 2, 3으로 쌓입니다. 회색 칸은 닫힌 화면이 남기고 간 구독입니다. 이때 음식을 하나 담으면 배지를 다시 그리는 함수가 세 번 불립니다. 그림의 '배지 갱신 3번'이 이 뜻입니다.

아랫줄은 닫을 때마다 해제한 경우입니다. 구독은 1, 0, 1, 0, 1로 하나를 넘지 않습니다. 음식을 담아도 배지는 한 번만 다시 그립니다.

해제를 잊으면 같은 알림이 두 번, 세 번 뜹니다. 명단에 남은 함수가 닫힌 화면의 데이터까지 붙잡고 있어서 앱도 점점 느려집니다. [3장](ch03.html)에서 본 메모리 누수입니다.

그래서 **만든 곳이 치웁니다.** 화면을 열 때 만든 것은 그 화면을 닫을 때 치웁니다.

치울 것은 구독만이 아닙니다. 맞춰 둔 타이머는 꺼야 합니다. 열어 둔 파일은 [3장](ch03.html)에서 본 것처럼 닫아야 합니다. 다른 컴퓨터와 이어 둔 연결도 끊어야 합니다. 이렇게 **쓰고 나서 치워야 하는 것**을 통틀어 **자원**(resource)이라고 합니다.

코드에서는 만드는 말과 치우는 말이 짝을 이룹니다.

| 만드는 말 | 치우는 말 | 하는 일 |
|---|---|---|
| `addEventListener` | `removeEventListener` | 버튼 누름 같은 일을 알려 달라고 한다 |
| `setInterval` | `clearInterval` | 되풀이하는 타이머를 맞춘다 |
| `subscribe` | `unsubscribe` | 구독한다 |

왼쪽 낱말을 봤는데 오른쪽 낱말이 안 보이면 AI에게 "이건 언제 치워?" 하고 묻습니다. 게임을 다시 시작할 때마다 캐릭터가 점점 빨라지는 것도 같은 버그입니다. 끄지 않은 타이머가 쌓여서 움직이는 코드가 두 번, 세 번씩 불립니다.

## 늦게 도착한 응답: 번호표로 걸러 내기 {#stale}

지도 앱의 검색창에 '서울'이라고 쳤습니다. 앱은 검색을 맡은 컴퓨터인 서버에 "서울을 찾아 줘" 하고 요청을 보냅니다. 이어서 '역'을 치자 "서울역을 찾아 줘"라는 요청이 또 나갔습니다.

서버가 돌려주는 답을 응답이라고 합니다. 그런데 '서울역'의 응답이 먼저 오고, '서울'의 응답은 한참 뒤에 왔습니다. 화면은 '서울역' 결과를 잠깐 보여 주다가 '서울' 결과로 바뀌어 버립니다. 검색창에는 아직 '서울역'이라고 적혀 있는데 말입니다.

::: {.fig src="stale-response.svg"}
먼저 보낸 요청의 응답이 나중에 도착했습니다. 오는 대로 보여 주는 화면은 옛 결과로 덮이고, 번호를 확인하는 화면은 그대로입니다.
:::

0초에 1번 요청 '서울'이, 0.2초에 2번 요청 '서울역'이 나갑니다. 0.4초에 2번의 응답이 먼저 옵니다. 0.8초에 1번의 응답이 뒤늦게 와서 화면을 옛 결과로 덮습니다.

요청은 **보낸 순서대로 돌아온다는 보장이 없습니다.** 은행이나 병원에서 쓰는 번호표가 해결책입니다.

1. 요청을 보낼 때마다 번호를 붙입니다. '서울'은 1번, '서울역'은 2번입니다.
2. 가장 마지막에 보낸 번호를 기억해 둡니다. 지금은 2번입니다.
3. 응답이 오면 그 번호가 기억해 둔 번호와 같은지 봅니다. 같으면 보여 주고, 다르면 버립니다.

0.8초에 온 1번 응답은 번호가 달라서 버려집니다. 화면에는 '서울역' 결과가 그대로 남습니다.

검색어, 탭, 날짜처럼 빠르게 바꿀 수 있는 것에는 모두 이런 일이 생길 수 있습니다. 기다림이 끼어드는 일은 [11장](ch11.html)에서 더 다룹니다.

::: {.key}
기다림이 끼어드는 곳마다 물어보세요. **"이 응답이 도착했을 때, 화면은 아직 이 응답을 기다리고 있는가?"**
:::

::: {.deep title="'좋아요'는 왜 누르자마자 빨개질까요?"}
'좋아요'를 누르면 하트가 바로 빨개집니다. 이때 서버의 응답은 아직 오지 않았습니다. 앱이 "잘되겠지" 하고 믿고 화면부터 바꾼 것입니다. 응답을 기다렸다가 바꾸면 누를 때마다 앱이 굼뜨게 느껴지기 때문입니다. 이렇게 **응답을 기다리지 않고 화면을 먼저 바꾸는 방법**을 **낙관적 갱신**(optimistic update)이라고 합니다. '낙관'은 잘될 것이라고 믿는다는 뜻입니다.

실패했다는 응답이 오면 하트를 원래대로 되돌려야 합니다. 그래서 틀려도 큰일이 아닌 곳에만 씁니다. "결제 완료"처럼 틀리면 안 되는 표시는 서버의 응답을 받은 뒤에만 보여 줍니다.
:::

## 나눠 담기: 한 덩어리로 뭉친 코드 풀기 {#split}

서랍 하나에 양말, 충전기, 영수증을 다 넣어 두면 처음에는 편합니다. 물건이 늘면 양말 한 켤레를 찾으려고 서랍을 통째로 뒤집어야 합니다.

AI가 만든 코드도 이렇게 되기 쉽습니다. AI는 파일 하나에 모든 것을 이어 붙이곤 합니다. 기능을 더해 달라고 하면 비슷한 코드를 복사해 조금만 바꿔 덧붙입니다. 처음에는 잘 돌아가다가, 어느 날부터 한 곳을 고치면 다른 곳이 망가집니다.

코드를 한 줄씩 읽지 못해도 뭉친 곳은 알아볼 수 있습니다.

| 눈에 보이는 것 | 왜 문제인가 | AI에게 할 말 |
|---|---|---|
| 파일 하나가 수백 줄로 길어진다 | 고칠 곳을 AI도 잘못 짚기 쉽다 | "화면, 계산, 저장을 다른 파일로 나눠 줘" |
| 거의 같은 코드가 여러 번 나온다 | 한 곳만 고치면 나머지와 어긋난다 | "되풀이되는 부분을 함수 하나로 묶어 줘" |
| 함수 하나가 화면을 넘길 만큼 길다 | 여러 가지 일이 섞여 있기 쉽다 | "한 가지 일만 하는 함수로 나눠 줘" |
| 함수 밖의 변수를 여러 함수가 고친다 | 누가 값을 바꿨는지 찾기 어렵다 | "이 값을 고치는 길을 하나로 모아 줘" |

되풀이되는 코드를 묶는 것은 "같은 내용은 한 곳에만 적는다"를 코드에 쓴 것입니다. 함수 밖의 변수는 앞에서 본 전역 변수이고, 고치는 길을 하나로 모으는 것이 캡슐화입니다. 나눈 파일은 `import`라는 말로 서로를 불러 씁니다([초코딩 기초](code.html#import)).

나누는 일은 기능을 더하는 일과 따로 시킵니다. "하는 일은 그대로 두고 나누기만 해 줘"라고 말하고, 끝나면 전과 똑같이 돌아가는지 직접 눌러 봅니다. 이렇게 **겉으로 하는 일은 그대로 두고 속의 짜임만 고치는 것**을 **리팩터링**(refactoring)이라고 합니다. 시키기 전에는 [7장](ch07.html)에서 배운 커밋으로 돌아올 곳을 만들어 둡니다. 일을 작게 나눠 시키는 순서는 [30장](ch30.html)에서 다룹니다.

::: {.try}
AI에게 받았던 코드를 챗봇에 붙여 넣고 물어보세요. "아직 고치지는 마. 거의 같은 코드가 되풀이되는 곳과, 함수 밖의 변수를 고치는 함수를 모두 찾아서 표로 보여 줘." 코드가 없다면 먼저 "가위바위보 게임을 파일 하나로 만들어 줘"라고 해서 받은 코드로 해 봅니다.
:::

## 헷갈리기 쉬운 짝 {#pairs}

| 짝 | 차이 |
|---|---|
| 상태 / 화면 | 프로그램이 기억하는 것 / 그것을 보고 그린 그림 |
| 순수 함수 / 부수 효과가 있는 함수 | 계산만 한다 / 바깥의 무언가를 바꾼다 |
| 클래스 / 인스턴스 | 객체를 찍어 내는 틀 / 틀로 찍어 낸 객체 하나 |
| 상속 / 조합 | 통째로 물려받기 / 필요한 부품을 끼워 넣기 |
| 원본 / 파생 값 | 직접 적어 두는 것 / 원본에서 계산하면 나오는 값 |
| 얕은 복사 / 깊은 복사 | 겉 상자만 새로 / 안쪽까지 전부 새로 |
| 없음 / 실패 | 잘 찾아봤는데 없음 / 찾아보지 못해서 모름 |
| 기능 더하기 / 리팩터링 | 하는 일을 늘린다 / 하는 일은 그대로 두고 짜임만 고친다 |

## 실전 사례 {#case}

::: {.case title="취소를 눌렀는데 캐릭터가 바뀌어 있다"}
친구가 AI의 도움을 받아 작은 게임을 만들었습니다. 캐릭터 꾸미기 화면에서 모자를 골랐다가 '취소'를 눌렀는데, 캐릭터가 그 모자를 쓰고 있습니다. '저장' 버튼을 빠르게 두 번 누르면 저장도 두 번 됩니다.

1. **같은 일을 다시 일으켜 봅니다.** 이름만 고치고 취소하면 멀쩡합니다. 아이템 목록을 고쳤을 때만 문제가 생깁니다.
2. **목록이 하나인지 둘인지 확인합니다.** 초안과 원본의 아이템 목록을 비교해 보니 같은 것입니다. 겉만 복사한 얕은 복사였습니다.
3. **초안을 떼어 냅니다.** 꾸미기를 시작할 때 아이템 목록까지 복사합니다. 원본은 저장에 성공했을 때만 고칩니다.
4. **저장 상태에 이름을 붙입니다.** 대기, 저장 중, 완료, 오류로 나누고, 저장 중에 버튼을 또 누르면 무시합니다.
5. **확인합니다.** 모자를 고른 뒤 취소하기, 저장 버튼 연달아 누르기를 해 봅니다.

고친 뒤의 취소는 "되돌리기"가 아닙니다. 처음부터 원본을 건드린 적이 없으니 되돌릴 것도 없습니다.
:::

## 한눈에 정리 {#summary}

::: {.summary}
- **상태**는 프로그램이 기억하고 있는 것입니다. 화면은 상태를 보고 그린 그림입니다.
- 변수는 **스코프** 안에서만 보입니다. 변수는 그것을 쓰는 가장 좁은 범위에 만듭니다.
- 계산은 **순수 함수**로 하고, **부수 효과**는 눈에 띄는 한곳에 모읍니다.
- 상태는 **객체** 안에 숨기고(**캡슐화**) 정해진 창구(**인터페이스**)로만 고칩니다. '없음'과 '실패'는 구분합니다.
- **클래스**는 객체를 찍어 내는 틀이고, 찍어 낸 하나하나가 **인스턴스**입니다. 겹치는 코드를 줄일 때는 **상속**보다 **조합**을 먼저 떠올립니다.
- 같은 내용은 **한 곳에만** 적고 주인을 하나 둡니다. **파생 값**은 적어 두지 않고 계산합니다.
- **얕은 복사**는 안쪽을 함께 씁니다. 고치는 대신 새로 만들면(**불변 업데이트**) 실행 취소도 쉽습니다.
- 참·거짓 여러 개 대신 **상태 기계**로 적으면 있을 수 없는 상태를 만들 수 없습니다. 목록 화면은 불러오는 중, 성공, 비어 있음, 실패 네 모습을 모두 갖춥니다.
- 구독, 타이머, 파일 같은 **자원**은 **만든 곳이 치웁니다.** 늦게 도착한 응답은 **번호표**로 걸러 냅니다.
- 뭉친 코드는 파일과 함수로 나누게 합니다. 짜임만 고치는 **리팩터링**은 기능 더하기와 따로 시킵니다.
:::

## 확인 문제 {#quiz}

::: {.q}
체육 대회 점수판에 모둠원 네 명의 점수와 '모둠 합계'가 함께 적혀 있습니다. 한 명의 점수를 고쳤는데 합계는 그대로입니다. 어떻게 해야 다시는 이런 일이 생기지 않을까요?

::: {.a}
합계는 네 명의 점수를 더하면 나오는 파생 값입니다. 따로 적어 두지 말고, 볼 때마다 점수를 더해서 보여 줍니다.
:::
:::

::: {.q}
음악 앱에서 재생 목록 '공부할 때'를 복사해 '운동할 때'를 만들었습니다. 새 목록의 제목을 바꿔도 원래 목록의 제목은 그대로입니다. 그런데 새 목록에 노래를 넣었더니 원래 목록에도 그 곡이 들어 있습니다. 어떤 복사였을까요?

::: {.a}
얕은 복사입니다. 제목은 따로 옮겨졌지만, 노래 목록은 그것이 있는 곳을 적은 쪽지만 베꼈습니다. 노래 목록까지 새로 만들어 옮겨 담아야 둘이 떨어집니다.
:::
:::

::: {.q}
게임 캐릭터에게 '달리는 중', '점프 중', '쓰러짐'이라는 참·거짓 값이 따로 있습니다. 가끔 쓰러진 캐릭터가 누운 채로 달립니다. 구조를 어떻게 바꿔야 할까요?

::: {.a}
'쓰러짐'과 '달리는 중'이 함께 참이 될 수 있는 것이 원인입니다. 상태 칸을 하나만 두고 '서 있음', '달리는 중', '점프 중', '쓰러짐' 가운데 하나만 적습니다.
:::
:::

::: {.q}
채팅방에 다섯 번 들어갔다 나온 뒤부터 새 메시지가 올 때마다 알림음이 다섯 번씩 울립니다. 무엇을 의심해야 할까요?

::: {.a}
들어갈 때마다 "새 메시지가 오면 알려 달라"고 구독하고, 나갈 때 해제하지 않은 것입니다. 명단에 같은 함수가 다섯 개 쌓였습니다. 채팅방을 나갈 때 구독을 해제하면 됩니다.
:::
:::

::: {.q}
급식 앱에서 '오늘'을 눌렀다가 바로 '내일'을 눌렀습니다. 화면에 내일 식단이 나왔다가 잠시 뒤 오늘 식단으로 바뀌었습니다. 왜 그럴까요? 어떻게 막을 수 있을까요?

::: {.a}
먼저 보낸 '오늘' 요청의 응답이 나중에 도착해서 '내일' 식단을 덮었습니다. 요청마다 번호를 붙이고, 응답이 오면 가장 마지막에 보낸 번호와 같은지 확인합니다. 다르면 버립니다.
:::
:::

## AI에게 맡길 때 {#ai}

::: {.ai}
AI는 돌아가는 화면을 금방 만들어 줍니다. 하지만 상태의 주인과 실패했을 때의 처리는 빠뜨리기 쉽습니다. 코드를 쓰게 하기 전에 **상태부터 글로 적게** 하세요.

> 캐릭터 꾸미기 화면을 고쳐 줘. 코드를 쓰기 전에 두 가지를 표로 적어 줘. (1) 원래 캐릭터와 고치는 중인 초안처럼 이 화면이 기억하는 값마다, 원본이 어디에 있고 누가 고치는지. 계산하면 나오는 값은 따로 적어 두지 마. (2) 저장의 상태(대기, 저장 중, 완료, 오류)와 상태마다 눌러도 되는 버튼. 꼭 지킬 것은 세 가지야. 취소하면 원래 캐릭터는 하나도 바뀌지 않아야 해. 저장 중에는 버튼을 또 눌러도 한 번만 저장되어야 해. 아이템을 불러오는 중일 때, 하나도 없을 때, 실패했을 때의 화면도 만들어 줘.

**받은 답에서 확인할 것**

- 초안을 만들 때 안쪽 목록까지 따로 복사했는가.
- 참·거짓 값 여러 개가 아니라 상태 이름 하나로 적었는가.
- 개수나 합계처럼 계산하면 나오는 값을 따로 적어 두지 않았는가.
- 불러오는 중, 비어 있음, 실패일 때의 화면이 저마다 있는가.

**AI가 자주 하는 실수**

- 파일 하나에 다 몰아넣고 비슷한 코드를 복사해 늘립니다. 파일이 수백 줄을 넘으면 기능을 더하기 전에 나누기부터 시킵니다.
- 성공한 화면만 만듭니다. 인터넷을 끊고 열어 보면 실패 화면이 있는지 바로 드러납니다.
- 같은 값을 화면마다 따로 적어 둡니다. 한 화면에서 고친 것이 다른 화면에 안 보이면 의심합니다.
- 화면을 닫을 때 타이머와 구독을 치우지 않습니다. 같은 일이 두 번, 세 번씩 일어나면 의심합니다.
:::

## 용어 정리 {#terms}

::: {.terms}
상태 (state)
:   프로그램이 지금 기억하고 있는 것.

배지 (badge)
:   아이콘 옆에 붙어 개수를 알려 주는 작은 숫자 표시.

함수 (function)
:   여러 줄의 일을 한 묶음으로 만들고 이름을 붙인 것.

변수 (variable)
:   값을 담아 두고 이름을 붙인 칸.

스코프 (scope)
:   변수가 보이는 범위.

전역 변수 (global variable)
:   함수 밖에 만들어 어디서나 보이고 고칠 수 있는 변수.

클로저 (closure)
:   자기가 만들어진 곳의 변수를 붙잡고 있는 함수.

순수 함수 (pure function)
:   받은 값으로 계산만 하고 바깥은 바꾸지 않는 함수.

부수 효과 (side effect)
:   함수가 자기 바깥의 것을 바꾸는 일.

객체 (object)
:   데이터와 그 데이터를 고치는 함수를 한 묶음으로 만든 것.

캡슐화 (encapsulation)
:   안쪽 데이터를 숨기고 정해 둔 함수로만 고치게 하는 것.

인터페이스 (interface)
:   밖에서 쓸 수 있게 열어 둔 기능의 목록과 약속.

클래스 (class)
:   같은 모양의 객체를 찍어 내는 틀.

인스턴스 (instance)
:   클래스로 찍어 낸 객체 하나.

상속 (inheritance)
:   다른 클래스의 것을 통째로 물려받는 것.

조합 (composition)
:   필요한 기능을 부품으로 만들어 끼워 넣는 것.

원본 (source of truth)
:   같은 내용이 여러 곳에 있을 때 진짜로 삼는 한 곳.

주인 (owner)
:   원본을 고칠 수 있는 단 한 곳.

파생 값 (derived value)
:   다른 상태에서 계산하면 나오는 값.

얕은 복사 (shallow copy)
:   겉 상자만 새로 만들고 안쪽은 함께 쓰는 복사.

깊은 복사 (deep copy)
:   안쪽까지 전부 새로 만드는 복사.

불변 업데이트 (immutable update)
:   값을 고치지 않고 새 값을 만들어 갈아 끼우는 방법.

실행 취소 (undo)
:   방금 한 일을 되돌려 앞의 상태로 돌아가는 기능.

상태 기계 (state machine)
:   가능한 상태의 목록과 상태 사이를 넘어가는 길을 정해 둔 것.

발행·구독 (publish–subscribe)
:   바뀌면 알려 달라고 함수를 명단에 올려 두고, 바뀔 때 모두 부르는 방법.

자원 (resource)
:   타이머나 열어 둔 파일처럼 쓰고 나서 치워야 하는 것.

낙관적 갱신 (optimistic update)
:   응답을 기다리지 않고 화면을 먼저 바꾸는 방법.

리팩터링 (refactoring)
:   겉으로 하는 일은 그대로 두고 속의 짜임만 고치는 것.
:::
